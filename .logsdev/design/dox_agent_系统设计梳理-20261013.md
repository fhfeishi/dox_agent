# dox_agent 系统设计梳理：给机关资料管理部门用的好系统

日期：2026-10-13（query「2026-1013 1801」第二部分）。性质：基于本阶段对话与已实现功能的整体梳理和后续设计建议；“已有”指当前代码已实现并验证过，“建议”尚未实现，需与用户确认后分步实施。界面与交互的基本内涵见 `机关界面设计语言.md`。

## 一、我对这个项目的理解

dox_agent 是一个**本地部署的资料工作台**：把单位积累的项目资料（当前以国家自然科学基金结题报告为主，按领域分库）整理成可检索、可分析、可追溯的知识，再用它支撑三类日常工作——

1. **看清现状**：每个领域有哪些项目、解决了什么问题、用了哪些技术、取得了什么成果（四维整理 → 场景层级 → 五级技术谱系、路网、项目关系、年度分布）。
2. **产出材料**：问答、对比、技术研判、专项报告、情报分析，结论附原文出处，可导出 Word。
3. **把好关口**：对新申请书做形式审查和专业审查，指出问题、给出修改建议，并定位到原文。

它的价值不在“模型会写”，而在**每个结论都能回到原文**、**数字口径说得清**、**资料与结论能沉淀复用**。受限网络、本地部署、资料不出单位，是它区别于通用聊天工具的前提。

## 二、机关资料管理部门会遇到的问题

| 场景 | 实际困难 | 系统应提供的帮助 |
|---|---|---|
| 资料入库 | 格式杂（PDF/Word/扫描件）、命名不一、同一项目多份文件、批准号缺失 | 批量上传、自动识别项目身份，身份不明的集中待核对；扫描件明确提示不能读取 |
| 临时汇报 | 领导突然要“某领域这几年做了什么”，要在半天内出材料 | 领域总览一页纸、可复制的汇报大纲、图表可直接放进 Word |
| 定期总结 | 周报、月报、季度和年度总结要从零散成果里拼 | 按时间段自动汇总成果与任务，图表由系统统计，文字由模型起草、人工改 |
| 申请书审查 | 集中报送期工作量大、标准多、怕漏看、怕误判 | 默认模板一键审查，后台排队，问题定位到原文；“待核实”与“发现问题”分开 |
| 重复与相近 | 担心重复立项，但“相近”不等于“重复” | 相近项目作为线索列出，说明依据和差异，不自动下结论 |
| 口径与可信 | 同一数字在不同页面不一样；模型说得太满 | 同一对象处处同一口径；措辞中性；推断与事实分开；未知单列 |
| 新人上手 | 功能多、概念多（任务、模板、检查器、四维…） | 角色化入口、三步指南、业务语言命名、默认值能走通主路径 |
| 网络与安全 | 外网受限，资料敏感 | 本地文件为主；外部检索与模型调用说明数据流向；账号与权限分级 |
| 人员协作 | 谁在做什么、做到哪、谁来复核 | 任务归属与状态、复核标记、按人/部门的工作空间（待建） |

## 三、三类角色关注什么

### 领导（owner）——“这个领域整体怎么样，最近做了什么，下一步关注什么”

- **关注**：资料库建设进度；各领域的研究重点与分布（领域、环节雷达）；技术体系全景（谱系、路网）；投入（项目资金年度分布）；近期产出与周期总结；需要关注的问题。
- **习惯**：看图多于看字，一句结论加一张图；需要时下钻到依据；不操作、不维护。
- **成功标准**：五分钟内能向上级说清一个领域的现状与近期工作，且说得出依据。
- **已有**：领导视图三区（资料库建设、领域分析五视角＋雷达、近期工作＋图表＋总结报告）；自 query 1842 起可经“工作台 ▾”使用对话、分析、审查。
- **建议**：只看“已发布”的报告（见五、2）；总结报告可订阅（每周一自动生成，见五、6）；一页纸汇报导出。

### 管理员 / 小组长（admin）——“哪些事要处理，关键技术与缺口在哪，产出质量如何”

- **关注**：资料库维护（过期的谱系、未归类条目、身份待核对、导入失败）；任务进度与失败；各领域的关键技术、配套技术、缺少技术路线的问题；组员产出的质量与覆盖；对领导的周期汇报。
- **习惯**：先看待办，再看细节；需要正反两面的判断和可执行建议。
- **成功标准**：每天打开就知道要处理什么；能在发布前把关；能用系统产出给领导的总结。
- **已有**：管理视图四区（工作概况＋需要处理、关键技术＋雷达、年度分布、近期工作＋总结报告）；资料库维护限管理员。
- **建议**：报告复核与发布（五、2）；任务分派与归属（五、3）；按领域的“缺口清单”（缺技术路线的问题、证据薄弱的结论）一键转为分析任务。

### 用户（资料管理、项目实施人员）——“把我手上的事办完，办得快、办得对”

- **关注**：上传和整理资料；找资料、问问题；审查申请书；写分析报告并导出；回到上次没做完的工作。
- **习惯**：任务导向，最怕概念多、跳转多、等待时不知道进度。
- **成功标准**：不求助能独立完成“上传→审查→看报告”“提问→得到带出处的答案”“选任务→生成报告→导出”。
- **已有**：对话工作台（按问题自动选库）、资料库工作区、存量分析（精简任务卡）、三步审查、任务进度与报告中心。
- **建议**：“我的工作”首页（我最近的会话、报告、审查与进度）；报告提交复核；常用问题模板库。

## 四、信息架构与共同的对象

```
资料库（领域） ─ 资料文件 ─ 项目 ─ 四维条目（场景/问题/技术/成果）
      │                              └─ 场景层级、五级技术谱系、路网、项目关系、年度分布
      └─ 被引用于 ─ 分析报告 / 审查结果 / 总结报告（成果库）
时间段（近 3/7/30 天、周、月、季度、年）贯穿成果与任务
角色（领导/管理员/用户）决定看到的深度，不改变对象和叫法
```

导航保持稳定：管理员“管理视图→首页→对话工作台→资料库→存量分析→资料审查→情报分析”；用户落在对话工作台；领导落在“资料库建设、领域分析、近期工作”，经“工作台 ▾”进入工作台。右侧面板统一承载原文、报告、模板、项目详情的预览。

## 五、功能设计：调整与新增（按优先级）

| 优先级 | 功能 | 解决的问题 | 要点 |
|---|---|---|---|
| P1 | 1. 口径一致性检查 | 同一页面两个数字不一致会损害信任 | 同一对象统一计数来源（本轮已把雷达与要点卡统一为谱系口径）；数字旁注明口径 |
| P1 | 2. 报告复核与发布 | 领导看到未经核对的模型结论 | 报告状态：草稿→待复核→已发布；领导视图只显示已发布；管理员在报告中心复核 |
| P1 | 3. 任务归属与“我的工作” | 不知道谁在做什么 | 报告、会话、审查记录创建者；用户首页显示“我的”；管理员可按人查看（不等同于权限隔离） |
| P2 | 4. 管理员分析意见 | 只有统计，没有判断 | 依据资料库与成果库，由模型生成正反两面意见、问题与方案，按需生成并保存为报告（同总结报告机制） |
| P2 | 5. 缺口转任务 | 发现缺口后还要手动组织问题 | “缺少技术路线的问题”“证据薄弱的结论”一键生成对应分析任务 |
| P2 | 6. 定期总结 | 每周手动生成 | 管理员设置每周一/每月初自动生成上期总结，标为待复核 |
| P2 | 7. 一页纸汇报导出 | 临时汇报 | 领域总览＋雷达＋要点＋近期工作导出为 Word/图片 |
| P3 | 8. 部门工作空间与数据隔离 | 千人规模下的数据边界 | 先做个人/部门/全单位三级共享；需单位确认部门结构 |
| P3 | 9. 操作留痕 | 合规与追责 | 入库、删除、发布、权限变更记录 |
| P3 | 10. 容量与队列 | 集中报送期并发 | 持久化任务队列、按人配额、重复提交抑制；依据实测负载确定 |

## 六、交互上要坚持的几件事

- **主路径用默认值走通**：默认模板、默认资料库（按问题自动选择）、默认时间段（近 7 天）；只在真有歧义时让人选择。
- **一屏一个主操作**：如“开始审查”“生成近 7 天总结”；维护类操作收在“管理”菜单。
- **先结论后依据**：一句话结论＋一张图在前，列表与原文在后；任何数字可下钻。
- **等待可见、离开可回**：长任务进入队列，顶部“任务进度”可随时查看。
- **不夸大**：模型文字标明“由模型撰写、需人工核对”；“已解决”写作“报告所述已解决”。

## 七、本轮（query 1801）已落地

- 领导、管理员视图的领域总览与关键技术页加入“应用领域分布”“业务环节分布”两张雷达图；近期工作加入“各领域工作量”“按日/按月产出”图表。
- 新增周期总结报告：按所选时间段汇总分析报告与审查任务，系统统计图表数据，模型只写关注重点、结论联系、已完成、进行中、遗漏与建议；报告中的图表在网页中直接绘制，导出 Word 时转为表格；领导与管理员均可生成，只在点击时调用模型。
- 发现并修正：雷达图与要点卡对同一领域给出不同项目数（场景归纳口径 vs 谱系口径），统一为谱系口径；领导账户登录后后台自动保存会话被只读规则拒绝，改为领导账户不写会话。

## 八、需要确认的问题

1. 报告是否需要“待复核→已发布”流程，领导只看已发布的？
2. 部门结构是怎样的（几个部门/小组，资料是否按部门分）？这决定数据隔离的做法。
3. 定期总结是否需要自动生成（每周一、每月初），还是保持手动？
4. 管理员分析意见（正反两面、问题与方案）是否现在启用？它与总结报告一样需要调用模型。
