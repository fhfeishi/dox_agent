## 初次审查结论（当时快照；执行顺序以末尾裁决及03为准）

1. **现在的瓶颈是“没有可以统一修改的地方”，不是功能少。**
   - 组件里硬编码颜色 239 处，任意像素字号 10 种，主要正文是 11–13px；
   - 导航按角色写了三套，首页复制了三份；
   - 同一个去处有三到四个名字。
   - 所以每一轮只能逐个调整按钮和卡片，10-19 的改名需求也是这个原因造成的。
2. **最严重的系统缺陷是任务执行模型不统一（S1）。**
   - 对话和报告随 HTTP 连接执行，用户关掉页面，任务就中止（`main.py:2017`）；
   - 审查用线程，可以中断恢复；
   - 导入和四维提取的状态只存在内存里。
   - 设计文档承诺的“提交后可以离开”目前只对审查成立。
3. **后端的结构问题集中在三处：** 99 个路由写在一个 `create_app()` 闭包里，应用状态分散在 10 个以上的 SQLite 文件中且没有迁移机制，权限靠路径正则。前端的对应问题是 1375 行的全局 store 被 36 个组件直接使用。
4. **质量基础可以依靠，但缺少统一入口。** 本轮 pytest 308 项、前端测试 47 项、tsc 全部通过，ruff 67 项。浏览器脚本仍然只能手动运行，10-17 记录的两个失败没有处理。所以第一步必须是 `check.sh`，否则后面的重构没有回归保护。
5. **路线：** 基线收口 → 系统设计确认 → 骨架重构（后端和前端并行）→ 设计系统与界面 → 主流程验收（G2，进入 2-product-demo）。10-19 的首页需求不必等待，可以作为设计系统的试点先做。
