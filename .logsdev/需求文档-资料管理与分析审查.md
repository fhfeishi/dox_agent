## 1. 产品目标与使用者

主要使用者是资料管理人员，不要求具备编程、提示词或检索算法知识。系统应提供整理好的信息、现成问题、可点击的分析目的和有层次的审查结果，减少填写和反复上传。

本次业务目标：
1. 以自然科学基金项目资料为重点，方便查看场景、问题、技术、成果，以及立项年份、经费分布和项目联系。
2. 按预置模板分析现有资料；结合外部信息与资料库形成情报分析报告。
3. 面向自然科学基金申请、企业合作投标，分别开展形式审查与专业审查，并明确指出材料中的问题和依据。

“一眼看到归纳、点击查看项目、点击回到原文”是资料管理主路径；“选择目的、确认范围、得到报告”是分析主路径；“上传材料、选择要求、查看问题与修改建议”是审查主路径。

## 2. 主界面与模块归属

### 2.1 五个一级入口

| 入口 | 与当前界面的关系 | 主要内容 |
| --- | --- | --- |
| 对话 | 保持现有入口与基本使用方式 | 提问、追问、查看依据 |
| 资料库 | “知识库”更名 | 分类库卡片、四维归纳、时间经费、项目关系和资料管理 |
| 存量分析 | “任务”更名并调整内容 | 现有资料的四维分析、分析模板、统一分析成果及回收站 |
| 资料审查 | “形式审查”更名 | “形式审查”“专业审查”两个独立入口及审核记录 |
| 情报分析 | 新增 | 上传一个或多个外部信息，结合资料库与模板生成报告 |

**成果归属已由用户确认**：取消独立“成果”一级入口，统一成果列表和回收站放在“存量分析 → 分析成果”；情报分析生成的报告也收录于此。情报分析页可提供“查看本次报告/查看全部分析成果”的快捷入口，不建立第二份成果存储。

普通用户界面删除 Prompt/Skill 入口及管理页面，不要求用户配置这些资源。已有任务依赖的运行资产与用户数据不因界面隐藏而销毁；无调用代码可随实施清理。若另需销毁后台资产，应作为独立数据操作明确范围。

### 2.2 界面降噪

- 默认显示资料范围、归纳内容、可用操作、状态和下一步。
- 模型名、token、版本哈希、内部任务 ID、调试字段不占首屏；必要的追溯信息可展开查看。
- 不删除原文依据、规则出处、检查范围、未完成项和版本变化提示。
- 高频问题展示为按钮或卡片；自由输入为补充功能。
- 页面切换、图表点击和原文返回保持浏览状态，不自动改变运行中的分析范围。
- 颜色同时配文字和图例，用户无需靠辨色理解状态；鼠标、键盘均能操作。
- 长信息通过分层、分组和展开阅读整理，不以删除业务内容达到简洁。

## 3. 资料库：自然科学基金项目管理

### 3.1 一级分类与项目身份

**R-LIB-01**：保留 AI与医疗、AI与机器人自动化等一级库卡片及已有资料归属。点击库卡片进入该库的二级页面，不要求输入问题。

**R-LIB-02**：业务统计以项目为单位。同一基金体系中，同批准号的摘要、报告和补充文件关联为一个项目，保留全部文件出处；无批准号或信息冲突的项目待核对，不按相似标题自动合并。

项目详情应能查看名称、批准号、负责人、单位、类型、起止年份、资助金额及口径、关联文件、四维内容和原文。缺失信息标明缺失，不补造数据。

**R-LIB-02a 多文件汇总**：保留文件级提取与版本证据，项目页分来源汇总。摘要中的预期与结题报告中的已取得并列显示为不同来源/阶段，不把一个文件的状态覆盖整个项目；经费口径或数值冲突并列展示，未确认前不进入该口径资金统计。一个文件更新只使该文件的提取及依赖它的标签/关系失效，其余文件的有效证据保留。项目是否完成四维整理按全部关联文件覆盖计算，不由某一文件成功推断。

### 3.2 二级四维归纳

**R-LIB-03**：二级页面必须提供场景、问题、技术、成果四维内容的归纳与分类，展示归纳条目、关联项目数量和代表项目，而不是只列文件名称。

推荐布局为“四维总览＋维度详情＋关联项目＋原文检查器”，具体排版可在设计阶段调整，但须完成以下点击路径：

选择库 → 选择维度 → 选择归纳条目 → 查看关联项目 → 查看项目四维与原文 → 返回原位置。

| 维度 | 业务含义 | 颜色 |
| --- | --- | --- |
| 场景 | 应用环境、服务对象、疾病或业务情境 | 红色 |
| 问题 | 项目试图解决的困难、限制和痛点 | 蓝色 |
| 技术 | 方法、路线、数据及关键技术要素 | 绿色 |
| 成果 | 项目研究产出及状态、指标与条件 | 黄色 |

**R-LIB-04**：一个项目可属于多个条目。按项目去重计数，显示分母和统计范围，条目数不能直接相加。未整理、整理失败、原文更新和原文未提及须区分。

**R-LIB-05**：成果必须区分“已取得”“预期”“原文未明确”，保留数值和验证条件；不得将拟开展工作归为已实现应用。这里的成果是研究产出，与本工具的“分析成果”区分。

同义归并或人工字段确认不能覆盖原始提取和证据；首批可按现有原词归一计数，不要求先建设通用术语管理平台。

### 3.3 时间与经费展示

**R-TIME-01**：横轴以项目起始年定位。文件名 2021—2025 对应 2021 年区域。纵向位置反映资助金额，同一口径下经费越多位置越高。

**R-TIME-02**：按四维分别提供视图，采用红、蓝、绿、黄配色。可通过维度切换或并列小图实现，不要求首屏同时堆四张大图。

一个项目在同一维度视图中只显示一次；多标签不重复生成多个项目点。相同位置的项目可通过数量提示和展开列表解决重叠。经费越高不等于技术更先进或项目质量更高。

**R-TIME-03**：图表可交互，至少支持年份/条目选择、项目详情、原文查看、项目列表联动及重置。只读静态截图不能满足此需求。

**R-TIME-04**：金额、单位、币种与经费口径明确且有出处。批准资助、总经费、直接费用和申请预算不能混为同一数值；金额缺失不画为 0；未知时间或金额单列待核对。

**R-TIME-05**：图与列表采用同一筛选范围，分别显示已识别项目数、当前维度有有效证据项目数、当前口径可绘图项目数，另列缺批准号/冲突身份、金额缺失/冲突、未整理/失效数量。分母随统计目的变化，不能统一排除所有信息不全项目，也不能把部分覆盖写成全库分布。模型检索样本不能作为这些分母。

资料库时间视图按立项年；已有报告“项目区间与年份窗口相交”的语义继续明确显示，两者不混用。

### 3.4 四维项目关系

**R-REL-01**：在库内按四维展示项目之间可解释、可追溯的联系，支持简单知识图谱以及等价的列表阅读方式。

**R-REL-02**：首批关系表达为“共享场景”“针对相同问题”“使用相同技术条目”“涉及同类成果”。选择一个项目或条目可查看局部相关项目，点击关系查看双方依据。

**R-REL-03**：标签共现、同名方法或模型相似建议不能直接成为因果、继承、优劣或重复立项关系。语义相近但未经核对的关系须标为候选。

**R-REL-04**：同一项目多文件不能产生自相似关系；原文更新后旧关系失效；不展示无法回读的伪引用。图谱可局部展开，不要求全库所有项目两两连线或引入图数据库。

## 4. 存量分析：围绕现有资料与四维任务

**R-ANA-01**：将现有任务能力组织为资料管理人员能理解的分析目的，核心围绕场景、问题、技术、成果；保留必要的对比、趋势与报告功能。

**R-ANA-02**：普通任务通过模板和预设问题启动，用户选择库/项目、点击问题、确认已填好的范围即可运行，不要求自己编写提示词。

首批问题示例：
- 本库有哪些主要场景和问题？
- 这些项目主要采用哪些技术路线？
- 哪些成果已取得，哪些仍在计划？
- 这几个项目的场景、问题、技术、成果有何异同？
- 不同立项年份的关注点有什么变化？
- 已读资料中存在哪些痛点和薄弱环节？
- 按当前范围生成综合报告。

**R-ANA-03**：显示统计范围与实际阅读范围。确定性数量来自项目索引；模型解释、推断、可行性意见附来源和限制，不能写成全集事实。

**R-ANA-04**：“分析成果”统一管理存量分析和情报分析报告，支持预览、版本编辑、导出、移入回收站、还原及到期清理，沿用已有生命周期。推荐按结果来源筛选，不复制两套正文。

浏览图表或临时选择项目时，不悄悄替换已开始分析的资料范围。超过接口/上下文能力时不能静默截取前几个项目。

## 5. 情报分析：外部信息结合资料库

**R-INT-01**：新增独立入口，允许上传一个或多个外部信息文件；可补充粘贴文字。系统提取摘要与分析对象，用户以点击方式核对。

**R-INT-02**：用户选择分析模板和资料库，至少支持：
1. 技术背景分析；
2. 国内外研究现状分析；
3. 可行性分析；
4. 痛点/薄弱点分析；
5. 包含上述内容的综合报告。

**R-INT-03**：提供默认模板，支持用户上传模板、预览、修改并保存自己的模板。模板选择时能明确预期章节和用途，用户不必操作 Prompt/Skill。

三类模板不得混淆：分析任务模板定义分析目的；报告模板定义报告章节和呈现；申报书模板规定被审查材料的格式与大纲。上传模板的支持格式及复杂格式保真要求，结合真实样本确定。

**R-INT-04**：一次上传的多份外部信息组成同一次分析输入，允许逐份查看、移除或替换。文件角色不明确、相互冲突时提示用户确认，不自动覆盖。

**R-INT-05**：输出整理好的报告，至少包含结论摘要、对应分析章节、对照项目、依据、条件与不足。生成后收录“存量分析 → 分析成果”，情报分析保留查看本次结果的快捷入口。

**R-INT-05a 输入持久化**：一次分析冻结输入文件 ID/版本/哈希、模板发布版本与库内引用版本。外部材料保存于 STATE_DIR 下受管理的输入存储，替换创建新版本，不覆盖旧报告所引正文。材料移除仅撤销之后分析的选择；仍被有效成果或回收站版本引用的输入不得清理。最后一个关联成果永久清理后，删除无引用且已移除的输入附件；清理与共享附件规则复用成果生命周期。未保存结果的暂存输入须有明确的清理期限及提示，不凭浏览器缓存保证回读。

**R-INT-06**：外部材料自述与资料库事实分别标明。上传材料默认不自动入库、不进入四维统计；无国外来源时明确未覆盖，不把英文资料自动视为国外研究。

补充公开资料由用户明确选择，沿用现有受控检索与可回读快照。项目起止时间、成果时间、文献发表时间和抓取时间分别处理。

## 6. 资料审查：业务场景与材料包

**R-REV-01**：在“资料审查”中提供“形式审查”“专业审查”两个独立入口，不把两类任务藏在同一个开关中。

**R-REV-02**：两类入口均预置以下业务场景：
- 自然科学基金项目申请；
- 企业合作项目投标申请。

各场景绑定实际发布方、年度/批次、类别、模板和要求版本。企业投标不能套用基金示例规则。

**R-REV-03**：一个申报材料包至少包含“申报书正文＋申报信息表”；依据实际要求收集附件。两类审核共享材料包和已确认元信息，不要求重复上传。

信息表应覆盖项目名称、负责人、申报单位、账户、申报时间、资金、专利成果等实际规定字段。用户可多选上传并确认文件角色；缺少材料与无法识别字段分别提示。

**R-REV-04**：正文与信息表字段冲突时并排展示两边原文，不能自动选一个覆盖。替换材料形成新版本，旧结果标记所依据的旧材料。

**R-REV-05 执行分离**：新运行须明确 formal / professional 类型。形式任务只执行材料完整性、指南和确定性核对及其复核；专业任务只执行技术主张、相近工作/政策证据、技术评议及其复核。共享材料包，不共享“审核已通过”状态。不以拆页面代替后台分离；重跑只执行指定任务并冻结新版本快照。

缺信息表时形式任务报告缺失，但技术正文可读时仍可运行专业任务。形式未全部通过不一律禁止专业审查；材料不可读取或技术主体缺失时明确提示相关任务无法开展。

## 7. 形式审查要求

### 7.1 检查范围

**R-FORM-01**：按预置申报书模板及申报要求核对正文、信息表和必要附件，覆盖：

| 类别 | 具体要求 |
| --- | --- |
| 文档与格式 | 实际文件类型、字体/字号等规定格式、文件大小 |
| 大纲与内容 | 必需章节、顺序、必填位置及按模板大纲撰写 |
| 字数与篇幅 | 按规定范围、单位和计数口径核对 |
| 负责人资格 | 学历等具体条件及所需证明 |
| 申报单位 | 单位数量、类型和必须包含的单位性质 |
| 申报时间 | 实际申报时间与规定截止时间 |
| 经费 | 上限、金额口径、单位、汇总和跨材料一致性 |
| 专利/成果 | 数量、去重、状态、归属与适用日期 |
| 信息一致性 | 正文、信息表和证明材料的同字段一致性 |

**R-FORM-02**：规则来自真实指南、招标/合作文件或明确认可的要求，附出处与适用范围。会议中的“本科、含高校且不超过 5 家、500 万、专利不少于 3”是条件示例，不是通用固定门槛。“专利 3 篇”的计量对象和单位须核对。

**R-FORM-03**：文件字节、数量、金额和日期等确定性内容用可复核方法检查；模型承担有依据的定位和语义核对。无法自动核查的字体、版式、证明真实性等明确标为未检查或待核实。

DOCX 文本块不等于实际页数，扫描 PDF 不能凭 OCR 文本确认字体；上传本工具的时间不等于正式申报时间。

**R-FORM-03a 实质交付**：金额/数量/日期/文件大小/实际页数等受支持规则须有真正的执行器、输入出处、计量口径和输出结果；已有 calculation 仅保持 pending 不算完成。程序确定的结论不能被模型无依据覆盖或降级；规则未绑定执行类型或可靠输入时保持待核实，不编造通过。

### 7.2 结果与定位

**R-FORM-04**：前端按申报书大纲和信息表字段分组，以“标题＋文本框/问题卡”呈现问题、要求、原文、修改建议。支持切换查看正文问题、信息表问题和跨材料冲突。

**R-FORM-05**：用文字状态配颜色或高亮区分发现问题、需要核实、已核对通过、未检查/不适用。整体显示检查覆盖与各状态数量，不把材料缺失或检查未执行计为通过。

**R-FORM-06**：点击问题定位原文。PDF 使用实际页，DOCX 使用段落/单元格；高亮须绑定文件版本。定位不可靠时显示章节与引文，不能跳到无关位置。

## 8. 专业审查要求

**R-PRO-01**：以申报书技术内容为重点，对照选定资料库及正式政策/文献，至少检查：
- 与已有项目是否高度相近、是否充分说明实质差异；
- 技术路线与当前参考路线的关系；
- 与选定规划/政策明确方向的对应；
- 非主流或非明确支持方向的开展必要性；
- 先进性依据、技术基线、指标和验证条件；
- 可行性、关键假设、风险和薄弱环节。

**R-PRO-02**：相近工作按目标、对象、数据、方法、指标、条件和成果状态逐项对照，呈现共同点、差异和无法判断项。检索分数和共享标签不能直接等同于重复工作。

## 14. query「2026-0930 2351」：以归纳展示为中心的界面方案（2026-10-02）

### 14.1 目标与现状差距

用户明确：面向领导与资料管理员，重点是信息归纳、可视化展示及由此展开分析。推荐使用同一界面的渐进展开，不增加领导版/管理员版两套模式。

### 14.2 推荐页面结构

1. 顶部：真实领域名称、简短库说明、当前年份范围；右侧「查找项目」「管理资料」。

3. 四维概览：场景、问题、技术、研究成果四张等权卡片，桌面 2×2，窄屏单列。每张显示本维度有证据的项目数、前三个主题及横向数量条、「查看全部」。顶部少量主题是预览，不隐藏全部入口。
4. 下方工作区：「主题归纳」「年度分布」「项目联系」。默认主题归纳，点击概览卡直接切换维度并定位工作区，保持年份筛选。
5. 项目或来源详情进入现有右侧检查器，沿「主题 → 项目 → 文件证据」返回，保留筛选和滚动位置；窄屏使用可返回的全宽阅读面板。

| 维度 | 页面回答的问题 | 主题内优先信息 |

### 14.4 主题整理的最小规则

- 保留文件级提取和原文；在其上维护每库、每维度的主题归属，不重写原文标签。
- 精确同名标签沿用现有合并。同义主题由系统提出建议，管理员勾选确认；不自动跨维度、跨库合并，也不首期建设通用术语体系。
- 主题名称、成员和人工确认可以撤销；重新提取只更新证据，不擅自覆盖人工归属。新标签先独立展示，可被加入已有主题。
- 一个项目可属于多个主题，同主题按项目去重。比例必须说明分母，多主题比例之和可超过 100%，不用饼图表现互斥分布。
- “无相关描述”“未整理”“提取失败”“来源已更新”分开呈现。缺失不归入“其他”后假装完成。
- 综合归纳按主题的来源版本与成员集合保存；变化只使受影响主题提示需更新。页面打开不自动触发模型，旧归纳显示更新状态，允许点开原有来源快照的前提是实际已保留；没有快照则说明来源已变化，不伪造旧原文。

经费图作为切换视图，保留原需求的横轴起始年、纵轴同口径金额、四维颜色及点击项目。只绘单位与口径可确认的数据，显示未绘数量和原因；经费高不表示质量高。大量金额缺失时，数量趋势仍然可读，不能为了填满图而猜单位。

项目联系先使用选中项目—共享主题—相关项目的局部视图，每条关系可以解释并查看两端来源。默认展示有限关联，并显示总数和“查看全部”；不以共同标签断言重复立项、技术继承或因果关系。无需一次绘制全库数百节点。

## 17. 四维层级结构与成果相关分析（2026-10-07）

依据 query.md「2026-1007 1241」。本节规定四维归纳的上下级结构与成果的二级分析页，不改变第 3 节的项目身份、来源版本、金额口径、分母与证据契约，也不改变四维定义与配色；设计落点见 [通用模板审查与资料归纳设计实施方案](通用模板审查与资料归纳设计实施方案-20261008.md)。

### 17.1 层级与追溯

**R-SCN-01 场景层**：一份分析的结论先归纳为 6 类场景。场景按“应用对象＋业务环节”命名，沿用资料库既有场景主题（红色）。场景可跨多个项目，一个项目可属于多个场景。6 类为首批期望数量；材料只支持更少场景时按实际数量显示并说明覆盖不足，不新增空场景凑数，也不把更少写成达标。

**R-SCN-02 问题层**：每类场景 3 个核心问题，全库合计 18 个；每类场景内为 2 个已解决问题＋1 个待解决问题。已解决＝库内已有项目对该问题给出方案或产出；待解决＝现有材料中没有有效方案或明确列为薄弱点。每个问题必须有原文支撑的说明与来源；无证据的问题不生成，不用相邻场景的问题顶替。

**R-SCN-03 技术层**：每个核心问题下 2–3 条典型技术路线，每条只给标题与一句话概要。标题用原文术语，不自造名称。每条至少关联一份原文（项目、文件、页或位置），可点击预览原文并返回原位置；多项目共用一条路线时按项目去重显示，不重复列项目。

**R-SCN-04 成果层**：每类场景给出标志性成果，典型 3–5 项，数量按实际证据调整，重点是突出标志性而非凑数。每项可追溯原文，并显示标志性依据（覆盖项目数、是否已验证、代表项目）。预期成果与已取得成果分列，沿用 R-LIB-05 口径。

**R-SCN-05 成果相关分析**：每类场景的成果区提供一处“相关分析”入口，点击进入二级页面，自动生成并展示该场景成果在八个方面的完成度：论文、专利、人才/团队、平台/基地、数据与样本、指标达成、标准/许可、转化与应用。页面按成果项分组呈现该场景的标志性成果，每个方面显示完成度四态：已取得／在研／仅预期／原文未提及，与 R-LIB-05 口径一致。每条结论带来源并可预览原文；无证据的方面显示“原文未提及”，不写 0、无或留空。

**R-SCN-06 二级页覆盖说明**：相关分析页显示参与归纳的项目与文件范围、生成时间与来源版本。来源更新后标注该场景与相关方面“需更新”，不静默改指新正文，也不丢弃原引用版本。

**R-SCN-07 共享数据契约**：资料库四维浏览、存量分析综合报告、情报分析报告使用同一套场景／问题／技术路线／成果实体与证据字段。同一对象在三处的名称、状态与证据集一致；人工归并与改名的结果在三处同时生效，不各自生成一套层级。

**R-SCN-08 配色**：新增的是三个维度的上下级展开，不新增维度颜色。场景红、问题蓝、技术绿、成果黄沿用；相关分析页用中性分组＋同一套语义色，不引入新色板。

### 17.2 验收

| 验收场景 | 验收结果 |
| --- | --- |
| 进入某库查看场景层 | 显示实际归纳的场景与核心问题数量（目标 6 类、18 个问题），并在覆盖说明中显式标注与目标的差距，不把更少写成达标 |
| 点开一个核心问题 | 2–3 条技术路线，标题与概要可回读原文，返回时回到原位置 |
| 查看某场景成果 | 3–5 项标志性成果，逐项可预览原文并显示标志性依据，预期与已取得分列 |
| 点击“相关分析” | 二级页按成果项展示八个方面与完成度四态，未提及项如实显示，可回读原文 |
| 来源更新后回读旧场景与相关分析 | 标注需更新，引用仍指向原版本 |
| 同一场景分别出现在资料库、存量分析报告、情报分析报告 | 名称、状态与证据一致 |

### 17.3 本节已定的口径

- 数量口径：6 类场景、每类 3 个问题（2 已解决＋1 待解决）、每问题 2–3 条技术路线、每类 3–5 项成果均为**目标值**，按实际证据生成。材料支持不足时按实际数量显示，并在覆盖说明中显式标注缺口；不为凑数新增无证据条目，也不因此把更少数量判为达标。
- 相关分析二级页采用资料库四维浏览下的深链视图（可刷新、可返回、可保留筛选与滚动位置）；改为抽屉属后续界面调整，不改变本节业务要求。
