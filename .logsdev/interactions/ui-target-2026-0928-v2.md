## 2. 设计语言

### 2.1 视觉风格

沿用现有"纸感中性 + 低饱和"：`--canvas` 底、`--surface-soft` 分区、发丝线分隔。

- **嵌套不超过 3 层视觉边框**：四维区域内部一律"无边框分区 + 标题 + 间距"。
- 阴影保持两级（卡片 hover `0 4px 12px rgba(15,15,15,0.08)` / 浮层 `0 16px 48px -8px`），不加深、不加玻璃拟态。

### 2.2 配色（维度色 + 状态色严格分离）

维度色**只用于标识**（3px 色条 / chip 底 / 图标底），**不铺大面积背景**：

| 维度 | 色条·图标底 | 文字·图标 | token（全部复用现有，不新增） |
|---|---|---|---|
| 场景 | `--tint-sky` #dcecfa | `--link` #0075de | ✅ `globals.css:43` |
| 问题 | `--tint-yellow` #fef7d6 | #9a6500 | ✅ `globals.css:45` |
| 技术 | `--tint-lavender` #e6e0f5 | `--purple` #7b3ff2 | ✅ `globals.css:42` |
| 成果 | `--tint-mint` #d9f3e1 | `--green` #1aae39 | ✅ `globals.css:41` |

**硬规则**：

- **维度色回答"这是什么"，状态色回答"它怎么样"，不得混用。**
- §10.2 要求可区分的三种状态：
  - `未提及`（原文没有该维度）→ 虚线描边 + `--stone` 文字 + 文案"原文未提及"，**不报红**
  - `待更新`（源版本变了）→ `--orange` chip
  - `提取失败 / 缺字段` → `--red`
- 维度色不作为唯一区分通道，必须同时有**文字标签 + 图标形状**。

### 2.3 字体与排版

新增 type scale（替换手写值，旧组件不动）：

| Token | 值 | 用途 |
|---|---|---|
| `--fs-display` | 26 / 22 | 页面标题、库名 |
| `--fs-title` | 16 / 14 | 报告卡标题、分区标题 |
| `--fs-body` | 13.5 / 13 | 条目说明 |
| `--fs-meta` | 12 / 11.5 | 计数、路径、时间戳 |
| `--lh-body` / `--lh-title` | 1.6 / 1.35 | 段落 / 标题 |

- **报告标题 vs 源文件名必须区分**（现状两者挤在同一个 `truncate` 里，`CorpusFiles.tsx:232`）：标题 `--fs-title` + `--ink` + semibold；文件名 `font-code` + `--fs-meta` + `--stone`。
- 计数类统一 `font-variant-numeric: tabular-nums`。
- 条目说明每行 40–60 中文字符（约 `max-w-[680px]`）。

### 2.4 间距与层级（最需要先做的基础设施）

现状间距全为魔法数字（`p-[15px]`、`gap-[11px]`、`mt-[18px]`…），四维嵌套会放大不一致。

- **4pt 栅格**：`--sp-1:4 --sp-2:8 --sp-3:12 --sp-4:16 --sp-5:20 --sp-6:24 --sp-8:32 --sp-10:40`
- **圆角三档**：`--radius-card:12` / `--radius-control:7` / `--radius-chip:999`
- **层级规则（越深间距越小）**：页面→区块 24；卡内→分区 16；分区间 16；分区内标题→正文 8
- **迁移策略**：只加 token，新组件强制使用，旧组件按批次迁移（避免一次性重构引入回归）

### 2.5 组件与图标

新增组件（复用现有 `Drawer` / `Pill` / `Button` / `Icon`）：

| 组件 | 职责 | 优先级 |
|---|---|---|
| `CorpusWorkspace` | 库内双视图容器（替代 `CorpusDetail` 抽屉） | P0 |
| `FacetNav` | 分面路径 + 面包屑/筛选标签（`facetPath` 渲染） | P0 |
| `ReportCard` | 报告卡：标题 + 原名 + 两维状态 + 四维完备度 + 简要技术/成果 | P0 |
| `FacetPanel` / `FacetSection` | Inspector 内四分区（纵向，可折叠） | P0 |
| `FacetChip` | 维度标识，含 `未提及` / `待更新` / `失败` 三态 | P0 |
| `ExtractBadge` | 提取状态 + 覆盖度（§10.4 要求显示实际文本处理覆盖） | P0 |
| `EvidenceLink` | 证据 → PDF 页码 / 解析正文位置（§10.2 要求不伪造页号） | P0 |
| `MatrixBoard` | 场景 × 问题聚合看板 | P2 |

图标（`Icons.tsx`，**24px 网格、stroke 1.6–2.0、无填充**，与现状一致）：
场景 `compass` / 问题 `crosshair` / 技术 `layers` / 成果 `trophy`。
**禁用 `alert-triangle` 表示"问题"维度**——"问题"是研究客体，不是错误，会与解析/提取失败的状态图标语义冲突。

## 3. 交互逻辑

### 3.1 信息结构

- **报告单元为主键**（`doc_id`），源文件路径降为次要信息。现状 `CorpusFiles.tsx:106-116` 用 `rel_path` 字符串 join 文件与索引、并为无源文件的索引"造"假行——应由后端返回结构化报告单元，前端不再兜底。
- **"有索引无源文件"必须显式成状态**，不能混进 `indexed`（§10.3 要求源文件缺失不贡献当前证据）。

### 3.2 操作路径与规则

| 动作 | 现状 | 调整 |
|---|---|---|
| 打开知识库 | 卡片 3 个等价入口（`CorpusGrid.tsx:281/290`） | 收敛为 1 个 → 主区 `CorpusWorkspace` |
| 切换库内视图 | 不存在 | 顶部 `资料 / 四维浏览`；**默认「资料」** |
| 筛选资料 | 无 | `FacetNav`：场景 → 问题 为主路径；技术/成果可切换为筛选维度 |
| 查看报告四分区 | 无 | 点报告卡 → Inspector `reportTarget` |
| 溯源 | 仅整篇预览 | 每条目 `EvidenceLink` → PDF 页码或解析正文位置 |
| 触发提取 | 无 | 报告级单份 + 勾选后批量；**按需触发**，上传/刷新/打开页面不自动全库提取（§10.4） |

**R1（关键约束）**：分面路径必须渲染为**面包屑 + 筛选标签**，报告卡始终在中央列表。**禁止**把"场景→问题"渲染成左侧树形目录——那会诱导用户认为报告只属于一条路径，与 §10.2「不强制一份报告只属于一条树路径」冲突。

**路径长度**：卡片 → 库内四维 → 报告 → 成果内容 = **3 次点击**。

### 3.3 状态反馈（两维正交）

| 维度 | 取值 |
|---|---|
| 入库状态（已有） | 待导入 / 已入库 / 解析失败 / 源文件缺失 |
| 提取状态（新增） | 未提取 / 提取中(n/total) / 已提取 / 待更新 / 提取失败 |

- 卡片级：`ExtractBadge` + 四维完备度 `3/4`（缺失项用虚线 chip 明示是哪一维）。
- 库级：顶部汇总条 `已提取 32 / 未提取 8 / 失败 2`，**失败项可点开看清单**（现状只有"部分失败" pill、无入口，`CorpusGrid.tsx:20`）。
- **进度显示在触发位置**（报告卡/行内），不能只在详情底部一行文字（现状 `CorpusDetail.tsx:222-227`）。
- 覆盖度按 §10.4 显示实际文本处理覆盖；未完整处理不标"已整理"，也不计入完整覆盖统计。

### 3.4 异常与空态

四种空态，文案与行动各不相同（现状只有一句通用文案 + `-mt-[120px]` 负边距 hack，`CorpusGrid.tsx:311`）：

| 空态 | 文案要点 | 行动 |
|---|---|---|
| 无知识库 | 还没有知识库 | 新建知识库 |
| 库内无源文件 | 该库还没有资料 | 拖放/选择文件（指向 `source/`） |
| 已入库但未提取 | N 份已入库，尚未生成四维信息 | 批量生成（按钮旁说明会调用模型） |
| 该报告无 target | 尚未生成 | 生成四维信息（单份） |

- **"未提及"≠失败**：某维度原文没有 → 虚线态 + "原文未提及"，**不报红、不隐藏整份报告**（§10.4）。
- 删除类操作：现状仅 `window.confirm`（`CorpusDetail.tsx:132/143`）；保留确认，但危险操作与常规操作**分组隔开**。

### 3.5 动效与反馈时机

- **hover 位移只给最外层**（`CorpusGrid.tsx:169` 保留）；四维内层分区只用背景/边框变化——嵌套元素一起位移会抖。
- 时长 `--dur-fast:120ms` / `--dur-base:200ms`，缓动 `ease-out`；Inspector 滑入沿用现有 `duration-300`（`App.tsx:54`）。
- 内容切换**不做高度跳变**（CLS）：报告详情用固定高度容器 + 内部滚动。
- **长任务时序（硬要求）**：点击后 ≤100ms 出现可见反馈 → >1s 显示 n/total → >10s 允许后台化，离开后回库级仍可见汇总进度。
- 全局遵循 `prefers-reduced-motion`；四分区用 `role="region"` + `aria-label`；chip 必带文字标签。

## 6. 接口契约（与 §10.5 三个职责对齐，草案）

`src/` 内只读检索**未发现** target 模型或接口（与 §10.1 结论一致）。UI 所需最小字段：

```
CorpusInfo += target_count / target_pending / target_failed / schema_target: string[]

① 读取库内四维列表与筛选计数
GET /api/corpora/{id}/facets?dimension=场景|问题|技术|成果
  → { dimension, values: [{ value, report_count }] }
GET /api/corpora/{id}/reports?facet=场景:xxx
  → [{ doc_id, title, source_name, index_status, extract_status,
       coverage: { processed, total },
       facets: { 场景: "done"|"empty"|"missing", … },
       digest: { 技术: "…", 成果: "…" } }]

② 读取单份 target 与证据
GET /api/corpora/{id}/reports/{doc_id}/target
  → { doc_id, version, source_hash, schema_version, coverage,
      facets: [{ key, status, items: [{ id, name, desc,
                 evidence: [{ page | start_line, end_line, quote }] }] }] }

③ 提交提取 / 失败重试
POST /api/corpora/{id}/target  { doc_ids: string[], force?: boolean }
  → { job_id }   // 进度沿用现有运行状态方式（§10.5）
```

UI 侧假设：同一文档版本 + schema/提示版本已成功时默认复用，用户显式重新提取才再调用模型（§10.5）；处理期间范围改变则拒绝发布过时结果。

## 8. 验收要点（对齐 §10.6）

1. 库卡片 → 四维浏览 → 报告 → 成果内容 ≤ 3 次点击；返回后**筛选位置保持**。
2. 「未提及 / 待更新 / 缺字段 / 提取失败」四态在视觉与文案上可区分。
3. 每条目可跳回原文并定位（PDF 页码或解析正文位置），**无可靠页码时不显示页码**。
