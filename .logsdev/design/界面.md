### 5.3 回答的资料检索过程（2026-10-20，用户要求）

回答上方的“资料检索”面板取代原“分析过程”步骤列表（理解问题 / 检索报告 / 组织答案 / 完成处理与各自耗时）。收起时一行：生成中写当前进展，完成后写“在 N 份资料中选出 k 份 · 检索词 …”。展开为四段：

1. 理解问题：检索词、范围（资料库、全部或限定 N 份、年份窗口）；
2. 找到资料：每份入选报告的引用编号与项目名（点开原文）、所属库 · 批准号 · 起止年 · 负责人、与检索词的吻合度条、含与未含的检索词、命中位置（页码与小节）；补查时再列一轮；
3. 核对覆盖：首轮未覆盖的词与是否补查，仍未覆盖时说明回答会注明不足；
4. 组织回答：依据几份报告的全文或片段、约多少字，另有几个网页快照。

数据来自服务端 `trace` 事件（`src/agent/graph.py` `retrieval_trace`），只陈述检索事实，不展示模型推理；随运行记录保存（`runs.trace`，回答完成后也在 replay 中），便于事后追溯。耗时、Token 与内部步骤收在面板底部的“技术信息”，仅管理员可见。截图：`verification/answer-trace/`。

### 5.4 统一资料预览（F3b）

首屏：标题、库色标与库名、类型、已确认的项目年份、正文。展开：大小、实际页数或文本块数、导入时间、读取/索引/归纳状态与版本。操作：查看原文、下载、基于此资料提问。PDF 的“页”与 Word 的“文本块”不混称；信息缺失时不猜测。

## 6. 前端结构：现状 → 目标

```
现状  frontend/src/  api.ts · reviewApi.ts · store.tsx · components/（68 个平铺）· styles/globals.css
目标  frontend/src/
        app/        路由、providers、外壳、入口配置表（§2）
        shared/     ui/（Button、StatusBadge、EmptyState、ErrorNotice、ScopeBar、ChartCard、Panel …）
                    api/（由 /openapi.json 生成的类型 + 查询 hooks）、copy.ts、lib/
        features/   home、library、analysis（chat、tasks、workspace）、results、review、intelligence、settings
```

| 状态层 | 负责 | 实现 |
|---|---|---|
| 服务端数据 | 会话、资料、运行、成果、统计 | 只用 TanStack Query，不复制进 context |
| 工作上下文 | 浏览的库、分析范围、当前任务 | URL 参数 + 服务端运行记录；一个很小的 `WorkContext` |
| 界面布局 | 右侧面板与返回栈、侧栏折叠、宽度 | `PanelManager` context，浏览器本地持久化 |

依赖规则（由 `check.sh` 中的 import 检查强制，不另加 lint 依赖）：`shared` 不导入 `features`；`features` 之间不互相导入；组件中不出现 `fetch(`。

## 8. 降级
