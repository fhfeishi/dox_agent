# 机关使用的界面与交互语言

日期：2026-10-13（query「2026-1013 1637」第一步）。状态：初稿，随实施逐条检验、修订。

本文回答“机关单位的界面应当具备什么内涵”，并把每条内涵落到可检查的设计规则上。它不是视觉规范手册；颜色、字体等以单位现有规范为准。

## 一、内涵

| 内涵 | 含义 | 在界面上意味着 |
|---|---|---|
| 层级清楚 | 先总后分、先结论后依据 | 每页从“总体情况”到“具体对象”到“原文依据”逐层展开；任何一层都能回到上一层 |
| 口径可信 | 数字和结论说清范围、分母、时间和来源 | 结论旁紧跟“按什么统计、覆盖多少、截至何时”；未知、未整理、未判定单独显示，不当作零或通过 |
| 措辞中性 | 描述事实，不替使用者下判断 | 用“报告所述已解决”“待研究问题”“项目报告所述阶段”，不用“突破”“成熟”“转化率”一类需要正式评估才能下的词 |
| 一处一事 | 一屏只办一件事，主操作唯一 | 每页一个主按钮；次要操作收进菜单或展开区；同一信息只在一处出现 |
| 时间感 | 工作按时间组织 | 近期工作可按近 3 天、近 7 天、近 30 天，以及本周、本月、本季度、本年查看；所有“近期”都依据真实日期 |
| 可追溯 | 从结论能回到原文 | 报告、项目、原文统一在右侧面板打开，关闭后回到原处，不跳离当前页面 |
| 稳定可预期 | 位置和叫法不随页面变化 | 顶部导航次序固定；同一对象处处同名；状态一律带文字（排队中、处理中、已完成、未完成） |
| 按角色给深度 | 不同岗位看不同层级，而不是不同系统 | 领导看总览与趋势，管理员看关键技术、任务节点与问题，员工看自己的工作台；三者共用同一套对象和叫法 |

## 二、三种视图的分工

- **领导视图**：资料库建设情况 → 领域分析（总览、技术谱系、路网形式、项目关系、项目资金）→ 近期工作（按时间段汇总成果报告与审查任务）。只读，偏上层。
- **管理员视图**（第三步）：在领导视图的基础上下沉到关键技术、配套技术、任务节点；依据资料库和成果库中的报告做客观归纳，给出正反两面的意见、问题与可选方案。
- **员工视图**：对话工作台、资料库、存量分析、资料审查、情报分析；暂不按人隔离（后续按部门设工作空间）。

## 三、本步的落地（领导视图）

1. **资料库建设**：一行全局数字（资料库、资料、项目、四维整理、有经费记录的项目），下接每个资料库一行：资料与项目数、四维整理覆盖、场景与问题数、技术条目数、立项年份范围、最近归纳日期。点一行进入该领域分析。
2. **领域分析**：一个领域一次只看一个视角——总览、技术谱系、路网形式、项目关系、项目资金——用同一行分段切换，不跳页面。
3. **近期工作**：选择时间段后先给一句汇总（几份报告、几项审查、涉及哪些领域），再分“已完成”“进行中/未完成”列出；报告在右侧打开。成果之间的联系与综合判断需要调用模型，放在下一步，由使用者主动生成。

## 四、检验方式

每条内涵对应一个可检查的问题，例如：“这个数字的分母是什么？”“这个词需要正式评估才能说吗？”“这个页面的主操作是哪个？”“近期是按什么日期算的？”实施后用截图逐条核对，并在真实用户试用时记录看不懂、找不到的地方，回到本文修订。
