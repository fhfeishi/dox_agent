## 1. 复核结论

五入口、统一成果归属、项目身份前置、形式与专业独立执行的方向继续成立。主要不足是：资料浏览仍主要是标签聚合；审查工作台缺少同页指南核对；审查结果过度收敛成通用意见卡，丢失了 grant-review 的专题层次和逐条证据。应补齐业务信息链，不以增加装饰卡片数量替代能力。

技术审查沿用当前专业审查运行类型 professional，建议界面标“专业审查（技术评议）”，不再创建第三种任务。自然科学基金/企业合作投标是业务场景，形式/专业是执行类型，两个维度分别选择。

本轮直接读取指定 ZIP 的 docs/01_REQUIREMENTS、02_WORKFLOW_UI、04_TARGET_GAP、05_NEW_CONTRACTS、06_ACCEPTANCE，及 source/frontend/App.tsx、ReportOverview.tsx；并对照当前 ReviewViews、reviewApi、review/routes、audit、presentation。归档代码与文档是参考资料，不把其集成指令或旧验收条件自动当成当前要求。未启动归档应用，不声称已验证原版视觉效果。

## 4. 工作台：让管理员点击完成准备

资料审查内保留两个明显入口“形式审查”“专业审查（技术评议）”，右上为“审查记录”“要求与依据管理”。指南与文献管理降为支撑入口，不与两类工作争夺首屏。

桌面结构：

    材料与基本信息                    本次审查依据
    [正文：已上传 / 查看 / 替换]       [搜索或选择指南 / 上传指南]
    [信息表：已上传 / 查看 / 替换]     [基金、类别、年度、版本、适用范围]
    [材料清点 / 字段冲突]             [检查项标题列表 / 条件 / 出处]
    [已识别信息，默认只展开待核对]     [展开编辑 / 未保存 / 保存启用]
    -------------------------------------------------------------
    本次范围与尚缺材料                            [开始形式审查]

专业右栏改为对照资料库、可选政策、明确选择的文献、评价时点和内部论证范围。沿用同一材料包，可复用上传结果，不再次强制上传。

准备信息块：
- 材料清点：正文、信息表、指南要求的其他附件分别列出“已提供/缺失/不适用”。首期不必实现任意附件工作流，未支持附件明确待人工核对。
- 基本信息摘要：项目名称、类型、年份、负责人、单位、申请金额。仅已有可靠信息默认填入；缺字段展开核对，不要求资料员抄写全文。
- 字段冲突：并列“正文值/信息表值/原文位置”；人工选择或更正保留来源，不悄悄最新覆盖。
- 指南就绪：适用场景、年度、已启用条款数、缺少引用文件、未保存修改。上传失败保留材料和原选择。
- 开始按钮：就地说明阻止原因。缺信息表可运行并列为待补；专业正文可读时不因资格附件缺失而阻止。年份、日期是否必填由已选规则决定，不能重新引入统一填表日期门槛。
- 未保存指南改动需要保存或撤销再执行；防止界面显示新规则、后端执行旧版本。重跑创建独立任务，不覆盖旧报告。

## 5. 报告共同结构

首屏标题区展示项目、任务类型、材料版本、规则版本、生成时间和运行状态；下方是一段有依据的审查摘要和“优先处理事项”。摘要没有可靠内容时不编造整体结论。

统计条：明确问题、修改建议、待核实、已检查通过；“不适用”可在全部结果中筛选。另列“结论复核未完成 N 项”，不混入材料问题数量。不能显示没有依据的总分、先进性分数或通过率。

专题导航固定在正文之前。按需选择页签，页签内再提供简短章节目录；不把所有信息堆成一条长页。问题数变化应与列表一一对应，同一问题跨栏目出现不重复计数。

意见卡固定阅读顺序：
1. 事项标题、所属章节或字段、结论状态。
2. 发现了什么：简短说明，不能只露修改建议却隐藏问题。
3. 要求是什么 / 对照依据是什么。
4. 申请书实际内容：原文、文件名、PDF 页或 Word 文本块。
5. 差异与判断：计量值、比较过程，或有证据的专业解释。
6. 如何修改：分行的可执行建议。
7. 查看依据：正文、指南、对照资料分别链接。
8. 有限范围与复核状态：仅在本条需要时出现，不重复整页免责声明。

卡片状态以文字+图标+边线表达。红用于明确问题、橙用于提醒、黄用于待核实、绿用于已核对通过；与资料库四维的语义配色分开，避免“技术绿色”被误认通过。

## 6. 形式审查：六个有内容的阅读层次

页签建议：审核概览｜正文与大纲｜信息表｜预算与计量｜依据与覆盖。

| 信息块 | 展示内容 | 数据与开发边界 |
| --- | --- | --- |
| 概览与处理清单 | 主要问题、缺失材料、优先修改事项、未完成检查 | 现有 findings 可分组，不虚构严重程度或排序权重 |
| 材料完整性 | 正文/信息表/附件/引用指南的提供状态 | 不能把“缺少指南引用文件”误写成“申请人缺少附件”；两类分别展示 |
| 正文大纲核对 | 模板应有章节、正文对应章节、缺失/顺序/内容要求 | 当前无完整章节映射，需要结构化位置；按指南大纲，不固定所有基金一套章节 |
| 信息表逐字段 | 字段、要求、实际值、出处、结论；正文与表单不一致并列 | 已有确认元数据可起步；负责人/单位列表、账户等不完整支持项单列，不声称已自动核验 |
| 预算构成与计量 | 科目、金额、单位、原表合计、程序合计、差额；公式逐条复算；字数/大小/日期等实测值与限制 | 复用 budget、calculation_findings、execution；需要补前端类型与渲染。总经费、直接费用、申请资助额不能混算 |
| 格式与覆盖 | 文件类型、实际大小、可确认页数、字体段落等支持状态；启用条款→结论→复核状态；未读/空白页块 | 已支持项展示测量结果；字体/排版缺执行器时标“本次未检查”，不是“发现不合格”或“已通过” |

预算图只在同口径、相同层级、可加总且非负时展示构成；总额与合计不一致时突出差额，不能用圆环闭合制造一致。已有反复计量问题保护程序结论，不受模型随意降级。

未可靠提取大纲时仍展示模板目录和“正文定位未完成”，不伪造章节对应。PDF 原文保留物理页；Word 仅定位文本块，未渲染时不承诺字体/版面高亮。

## 7. 专业审查：恢复技术评议的厚度

页签建议：审核概览｜技术专题｜相近项目｜政策与文献｜修改建议。
“技术专题”提供六个稳定问题入口，但没有分析结果时显示未覆盖，不用通用文字填满：

1. 研究问题与目标是否清楚。
2. 与已有项目的实质差异：问题、数据、机制、验证和落地场景。
3. 路线与政策方向：政策一致性、领域常见路线分别判断。
4. 非主流方案的开展必要性：独特需求、替代方案不足与可检验假设。
5. 先进性与验证充分性：对照、指标、数据、消融与可复现证据。
6. 可行性、依赖和薄弱点：数据可得性、资源、实施路径及失败风险。

当前提示词提出这些方向，但输出仅有自由标题卡片，不能可靠地按标题字符串分类。后续增加最小的专题标识与覆盖状态；允许一专题多条意见或证据不足，不要求模型每次恰好生成六张卡。

相近项目区：
- 上方显示本次检索范围、实际采用份数和可确认的去重项目数。
- 先挑少量直接相关项目展示对照表：当前申请主张｜已有项目事实｜共同点｜差异｜尚缺证明｜两端原文。
- 同项目多文件合并为一组，预期成果与已取得成果分列。共享关键词只是检索线索，不能直接标为重复。
- 无匹配明确显示“本次范围内未取得足够对照材料”，保留内部论证评价，不为填满页面强制找相似项目。

政策与文献区分三类证据：库内项目、正式政策条款、公开研究文献。每张技术卡可展开实际引用的证据；证据库库存不等于本次使用。显示已读材料类型（摘要/节选/全文）、有效日期、来源及未验证限制。未确认日期的材料不能证明某历史时点已存在该路线。

修改建议按申请书章节汇总，说明补什么定义、实验、对照或论证；不生成没有依据的固定指标门槛。首期只支持查看和导出，不增加“已整改/待审批”协作状态；再次上传修改稿应新建审核版本。

## 8. 视觉与交互规格

- 主区以标题、摘要、专题和意见卡构成四层层级；白色阅读底、浅灰专题底、轻边框，复用宿主色彩变量。
- 正文建议 14–16px、行距 1.6–1.8，辅助文字不压到难以阅读。明确问题默认展开说明和建议，通过项默认收起。
- 宽屏工作台双栏；报告主文+现有检查器，不再嵌套独立抽屉。资料管理员可同时比对结论与原文。
- 窄屏上下排列，专题导航可横向滚动但整页不能横向溢出；原文切入全宽阅读，返回恢复专题、筛选与位置。
- 大纲与信息表都有可点击行，选择后同步定位意见和原文；有定位数据才高亮，无定位明确告知。
- 加载、无问题、未执行、证据不足、执行失败分别设计空态。运行失败保留材料与条件，显示失败阶段及重新开始入口，不呈现绿色检查通过。
- 历史记录保留材料和要求版本，修改要求不会重写旧报告；下载 Word 使用相同意见与依据，原始 JSON 放运行详情中。

## 9. 最小工程调整与顺序

### D1：恢复已有信息的展示（先做）

组件在现有 ReviewViews 内拆为工作台、报告概览、形式专题、技术专题及共用意见卡，避免一个巨大组件继续扩展。复用现有路由、存储、导出与检查器；先补当前 API 已有字段的类型和渲染。

交付：任务独立专题导航、逐卡证据/basis、预算/公式、计量信息、覆盖与复核状态、独立记录入口；统计和锚点统一。此阶段不需要新模型推断。

### D2：补齐审查前确认及证据契约

交付：同页指南工作区、未保存保护、材料冲突核对、显式证据选择、文件与项目分别计数、历史时间约束、实际检索范围记录。旧自由意见保留原始快照，新增展示字段不能编造成旧报告已有结论。

### D3：增加真正缺失的审查能力

交付：大纲映射、双材料字段对照、技术专题覆盖标识、双端项目对照证据。字体版式另列明确支持范围，真实模板测过才开放完成声明。资料库主题归并与综合继续按原 §14 实施，不能为了报告显示先开发通用知识图谱平台。
