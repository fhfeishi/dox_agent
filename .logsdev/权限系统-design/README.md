# 权限系统 · 阅读权限申请与审批

只做一件事：**谁能读哪份资料，读多久**。没有密级、没有分级继承，可见性由「人的组」与「资料的组」是否相交决定；不可见的资料保留登记行，并在行上给出「申请阅读」入口。

## 已按对话确定的口径

- 科室 = 资料库；每个科室 5 个部门 = 4 个技术组 + 1 个宣传管理组。宣传组跨本库 4 组只读，不跨库。
- 一份资料可以挂多个组（跨组项目按实测占 35%–48%），可见 = 交集非空。
- 不可见 = 只显示登记信息（项目名、批准号、年份、单位、所属组），摘要、正文、成果、引用一概不出现。
- 管理员三员分立保留：系统管理员提案、授权管理员生效、审计员只读；管理账户不授业务权限。
- 不设资料库级权限管理员；审批落在「科室负责人」岗位职责上。

## 申请与审批链

```
用户看到锁定行 → 行内「申请阅读」→ 抽屉填期限与理由 → 科室负责人批 → 立即生效 → 到期自动回收
```

- 申请的对象是「资料 + 期限」，不是「角色」或「整组权限」；单次上限 20 份，避免一次要走整库。
- 期限 14 / 30 / 90 天，默认 30 天；到期前 3 天提醒，续期要重新批。
- 同库跨组：科室负责人一步批准；跨库：两个科室负责人 + 授权管理员。
- 驳回必须写理由，申请人能看到；被驳回 7 天内同一份资料不可重复申请。
- 审批台只显示申请理由、期限、影响面（该组还有多少同类资料未开放），不显示正文。

## 三个界面状态

1. 资料库列表：可读行（文档图标 + 打开）/ 锁定行（锁图标 + 申请阅读）/ 审批中（时钟 + 撤回）。锁定行仍然可点，点开是登记态卡片。
2. 申请抽屉：登记信息、为什么看不到（「该资料归属 X 组，你在 Y 组」）、期限、理由快捷语、审批路径。
3. 审批台：待办队列，单条通过 / 驳回，显示申请人与所属组。
