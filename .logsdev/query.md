#### 3. 卡片分组的含义与推荐模型

**“组”是知识库的展示集合，不是新知识库，也不是一个检索任务。** 组内仍然是一格一格的独立知识库；点开单库继续进入现有资料与“场景、问题、技术、成果”浏览。分组不改变 source、parsed、datadb、vectordb、target 的落盘。

| 模型 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 单层、单归属的手动分组 | 每个库只有一个展示位置，移动、计数、删除含义直观 | 不能同时放在多个主题组 | 首版采用 |
| 多归属集合（类似收藏集） | 同一个库可用于多个研究专题 | 同库重复出现、去重计数与排序更复杂 | 真实出现跨专题整理需求后再考虑 |
| 规则自动分组 | 新库可以自动归类 | 领域/名称变化会改布局，命名相似不等于资料相关 | 首版只建议归类，不自动提交 |

建议先支持任意命名的单层分组，例如“基金 · AI 专题”“近期整理”。不要预置无法从当前数据证明的机构、年份或主题分类。

- 每个库最多属于一个组；没有归属的库在“未分组”区展示，后者是系统视图，不是可删除的真实组。
- 组内库互相独立；组排序、组内排序是展示顺序，不修改默认新对话选库顺序。
- 创建、改名、增减成员都是显式操作；发现名称共同前缀时，可提出“把这些库放入一组”的建议并展示候选列表，确认后才写入。
- 示例可建议把目前 AI 各领域库归为“基金 · AI 专题”；成员必须来自实际返回列表，不能根据截图补造看不见的库。
- 首版支持“选择卡片 → 移入分组”和卡片菜单“移动到分组”。拖放可后置；若增加拖放，必须保留菜单操作和键盘操作，不让拖放成为唯一入口。

#### 4. 堆叠与散开的交互

**收起态**：一张组摘要卡片，背后两层错位轮廓。叠层数固定只表达“集合”，库数量以文字为准，不绘制 11 张重叠卡片。

- 正面显示组名称、库数、简短成员预览、可检索文档总数、异常摘要和“展开”按钮。
- 示例：“基金 · AI 专题 / N 个库 / 医疗、农业、材料… / 可检索 M 份 / 1 库需处理”。N/M 为服务端实际数据，不使用截图数值作固定指标。
- 背面偏移约 4px/8px，边界清晰、阴影很轻；组图标采用叠卡，单库采用书架，避免误认。
- 组菜单包含改名、管理成员、解散分组；菜单点击不触发展开。

**展开态**：原位置变为全宽组区块，标题固定在本区块顶端，成员卡片按正常网格铺开，保留其它组与未分组区。不是弹窗覆盖，也不是自由漂浮画布。

- 首版一次只展开一个组。切换组时收起前一组；用户能明确看出成员属于谁。
- 展开组区块占用新的完整网格行；其他收起组顺延，维持其相对顺序。
- 展开按钮保持焦点，可 Tab 进入成员；收起时若焦点在成员内，回到组触发器；触发器表达展开状态与成员数量。
- 展开/收起不进入知识库详情，不增加检索库，也不触发导入；成员上的“打开”才进入单库详情。
- 切回知识库页恢复本次浏览的展开组；刷新页面可记住展开偏好；浏览器返回单库总览时恢复来源组与合理滚动位置。
- 动画建议 160–220ms，仅用轻微位移和透明度表达展开过程。成员进入常规布局，不用旋转、扇形遮挡；系统减少动态效果时直接切换。
- 空组显示“尚未加入知识库”及“添加成员”；只有一个成员仍保留用户命名的组，不能擅自解散。

行为链：`组摘要 → 展开组 → 打开成员库 → 浏览资料/四维 → 返回原组`。与对话链独立：`成员库上的“与此库对话” → 新建单库对话`。

#### 5. 数据与状态：后续实现的最小充分底层逻辑

以下为拟议逻辑对象，**不是现有 API 或已存在字段**。现有库对象见 `frontend/src/api.ts`，身份与目录扫描见 `src/agent/corpora.py`。

| 对象 | 最少需要保存的信息 | 说明 |
| --- | --- | --- |
| 分组 | 稳定组 ID、名称、排序、顺序化的成员库 ID 列表 | 成员引用已有稳定库 ID；不用显示名或目录名作关系键 |
| 界面偏好 | 展开的组 ID、第二侧栏是否收起 | 属于本地展示状态，与分组内容分开 |
| 派生摘要 | 成员数、文档数、异常数、当前对话命中数 | 从当前库数据计算，不另存重复事实 |

建议分组内容由后端持久化到应用级 STATE_DIR，与现有应用元数据归属一致；采用一份带格式版本的轻量元数据即可，不为单用户小规模分组新建通用分类服务。具体文件/存储实现留到开发时确认。界面偏好可以本地保存；分组内容不能仅存在某个浏览器的临时状态中。

写入约束：成员必须能在当前库注册信息中定位、一个库只能出现一次；组改名不改 ID；修改成功后再更新正式展示，失败则保留原布局和用户输入。多个标签页读取最新状态后处理成员冲突，不能通过写入过期完整快照悄悄覆盖另一个操作。无需为此引入协同编辑体系。

| 变化 | 规定的行为 |
| --- | --- |
| 库改名 | 用 ID 保持归属，卡片显示新名称；若扫描结果显示 ID 改变，不凭相似名字重绑 |
| 库目录缺失 | 仍保留组内卡片，标“目录缺失”，禁止需要资料的动作；允许移出组 |
| 用户明确删除库 | 清理相应分组成员引用，沿用已有删库确认与资料保留逻辑 |
| 外部扫描发现新库 | 默认未分组；可给候选归类建议，不自动加入组 |
| 移出最后一个成员 | 留空组并提供添加/解散入口 |
| 解散分组 | 所有成员回到未分组；不删库、不移目录、不改对话范围；动作文案直接说明 |
| 移入其它组 | 原组移除、新组加入作为一次操作成功；失败时留在原组 |
| 分组读取失败 | 显示错误与重试，同时可浏览全部库；不要把读取失败当成空分组并覆盖保存 |

聚合口径：组文档数是成员库的计数之和，不宣称是跨库去重后的独立报告数；缺字段显示“未统计”，不能补成 0。部分成员失败则摘要写“1 库需处理 / 其余正常”等真实分类，不把整组伪装成全就绪；展开后必须能定位异常成员。

#### 6. 搜索、浏览与对话范围的边界

- 知识库页主搜索只过滤组名、库名、已有领域与类型；不是文档全文搜索，也不调用 LLM。
- 命中组名：展示整个组及实际成员；只命中成员：显示所属组并临时展开匹配成员，标“匹配 2 / 共 8 个库”。未匹配库不参与当前结果的文档计数。
- 若组名和成员同时命中，按组名命中规则展示全组；全局命中数按库 ID 去重。
- 搜索允许多个命中组临时同时展开，区别于普通浏览的一次一组；不写入用户的展开偏好。清空搜索恢复搜索前布局。
- 第二侧栏点组名只限定浏览集合，组标题显示当前位置并提供“全部知识库”返回。侧栏与主区共享过滤条件，避免两个不同搜索框同时控制不明范围。
- 无结果时显示清空搜索/返回全部；不能为搜索结果临时创建新组。
- “当前对话使用”只由实际 corpus_ids 决定；浏览中的库用边框/当前位置表达，不使用同一个标签。
- 首版组卡片不提供“与整组对话”：现有对话是 1–6 库，组可能更多。需要跨库时继续显式选择具体库，展示名称和数量；超限给就地提示，不能悄悄取前六库。
- 专项报告继续走现有单库选择；分组不成为报告生成范围，不改变四维提取粒度。

#### 7. 单库卡片与整体视觉整理

- 卡片标题保持真实库名称；同组具有已核对的完整公共前缀时，可在组标题/副标题显示公共部分，卡片突出差异部分，但悬停、焦点或详情可查看完整名称。搜索依旧按原名匹配；不改目录、不自动生成虚假的简称。
- 标题最多两行；类型/领域只显示有增量的信息。若领域完全重复标题，不再再写一遍。
- 常态状态用小点 + “就绪”；导入中、部分失败、目录缺失用文字徽标。异常始终可见，状态不能只靠红绿颜色。
- 计数固定为“可检索 X / 源文件 Y”，待处理/失败另加短提示，不混用“库数量”和“文档数量”。
- 卡片保留“打开”和“与此库对话”；“四维浏览”作为研究特色入口可常驻；添加资料、刷新、重命名、删除收入更多菜单，在详情也可达。减少每张卡片五个同权重操作。
- 卡片标题与“打开”统一进入现有库详情；轻量信息摘要由独立信息按钮进入检查器，避免一个标题在不同位置触发不同内容。
- 主区白色，二级侧栏用轻灰，最左导航与二级侧栏保持边界。复用 globals.css 现有语义颜色变量，集中调整字色、字号、边框和间距，不散落新的颜色常量。
- 普通说明提高到清晰灰色；标题约 28px、卡片标题 15–16px、正文 14px、辅助信息 12–13px。数值为建议，不宣称已达到可读性或对比度标准。
- 卡片圆角约 12px，内边距 16–20px，间距 16px；按主区实际可用宽度形成 1/2/3 列，优先保障长中文名称可读。
- 顶部只保留一套“新建库、分组、刷新”工具区；页面末尾重复的新建大卡片可移除，空页面保留明显创建入口。
