## 1. 首批交付：一条流程

```text
知识库 → 选择一份资料 → 生成四维信息 → 查看四分区 → 点击证据 → 返回原位置
```

- 这条流程通过**之后**，再增加同库筛选与批量处理。
- 四维列表**直接使用现有文档标识（`doc_id`）关联 target**；不把"全面重构文件管理接口"作为前置。
- 样式统一、分页、其他清理**按实际需要处理**，不列入首批。
- 不新增路由框架：`nav` + 现有库打开状态即可表达"库内视图"（见 §2）。

## 3. 数据语义：四件事必须分开（核心修订）

**取消「3/4 完备度」**——一份报告没有成果，不代表提取只完成了 75%。UI 不再呈现任何形式的"完成百分比"。

| 层面的问题 | 取值 | 呈现 |
|---|---|---|
| ① 处理是否完成 | 未处理 / 处理中 / 已完成 / **未完成**（部分处理） | `处理状态` 徽标 |
| ② 原文是否提及该维度 | 有内容（**可点击**） / **未提及** | 四个维度标签 |
| ③ 模型返回数据是否有效 | 有效 / **提取异常**（缺字段、结构不合法等） | 分区内错误态 + 重试 |
| ④ 处理覆盖 | 已处理 / 总量（或分段覆盖说明） | 单独一行，不与维度标签混合 |

规则：

- **返回结构缺字段属于提取异常，不能当作"原文缺失"**——两者文案、颜色、可重试性都不同。
- **部分处理显示「未完成」**，不标"已整理"，不混入完整覆盖统计（§10.4）。
- 四个维度各自是一个标签：有内容 → 可点击进入该分区；无内容 → 显示"未提及"（虚线态，`--stone`，**不报红**）。
- **「文献成果」条目必须显示三态之一：`已取得` / `预期` / `原文未明确`**。这是研判的关键区别，接口必须提供该字段，前端不得自行推断。

## 4. 筛选契约（补齐）

首版刻意做小：

- **每个维度单选**，跨维度取**交集**；已选条件以标签呈现，**可单独清除**。
- **计数按去重报告数**（同一份报告不因多次出现被重复计数）。
- 必须区分两种关系，**不能混为一谈**：

| 情况 | 依据 | 呈现 |
|---|---|---|
| 同一报告**同时提到**某场景与某问题 | 仅两个维度各自命中 | 称「**同时包含**」，不画成路径 |
| 原文**明示**该问题属于该场景 | 原文支持的关联 | 才可呈现为明确的**关联路径** |

- **关联由详情接口返回**（`relations`），前端**不得**根据四个列表自行笛卡尔配对。
- 未确定关联的内容仍在报告详情中可见；不因没有场景或没有成果就隐藏整份报告（§10.4）。

## 5. 证据与定位（补齐能力）

- **固定一种正文定位口径**：证据携带 `文档版本 + 位置 + 引文` 三要素。
  - PDF 有可靠页码 → 跳页；
  - 否则 → 定位解析正文位置。
  - **提取时的正文位置未必等于现有阅读器的规范化行号**：服务端返回位置时必须指明所采用的定位口径（建议以解析正文的 chunk / 行区间为准），前端不自行换算。
- **版本不一致 → 显示「资料已更新」**，不用旧位置打开新内容（不伪造页号/行号）。
- **返回原位置**需要明确保留三件事（原 v2 的"天然不变"说得过满）：
  1. 主区筛选条件
  2. 当前选中的报告
  3. 列表滚动位置
  - Inspector 栈只保存检查器历史，不覆盖上面三项。

## 7. 运行边界（替换原"长任务时序"硬要求）

**只要求这些**：

- **点击立即反馈**（按钮进入禁用/进行中态，无延迟感知）。
- **批量显示真实完成份数**（`已完成 n / 共 m`），不编造百分比。
- **单份没有进度数据 → 显示「提取中」**，不伪造进度。
- 若采用服务端任务：**允许在当前应用内切换页面后继续查看**；**首版不承诺重启恢复**。
- **`job_id` 不够**：实施前必须补齐任务状态查询方式（端点/轮询或复用现有事件通道）。
- **不能假设可直接复用 `CorpusJob` 状态机**：导入任务与提取任务的状态不同，**显示形式可借鉴，状态语义不可照搬**。

## 9. 接口契约（草案 · 已按审核补齐）

`src/` 只读检索**未发现** target 模型或接口（与 §10.1 一致）。以下为 UI 所需最小集合，**均尚不存在**：

```
① 库内四维列表（首批用现有 doc_id 关联，不重构文件管理接口）
GET /api/corpora/{id}/reports?facet=场景:A&facet=问题:B
  → [{ doc_id, title, source_name,
       index_status,                       // 入库状态（已有）
       process: { status: "未处理|处理中|已完成|未完成", coverage:{processed,total} },
       facets: {                            // ②原文是否提及，不是完成度
         场景: { state: "has|未提及|异常" },
         问题: { … }, 技术: { … }, 成果: { … }
       } }]
  // 多条件：每维度单选，跨维度交集；计数按去重报告数

② 单份 target 与证据
GET /api/corpora/{id}/reports/{doc_id}/target
  → { doc_id, version, source_hash, schema_version,
      process: { status, coverage },
      relations: [{ from:{dimension,item_id}, to:{dimension,item_id}, basis:"原文明示" }],
      facets: [{
        key: "场景|问题|技术|成果",
        state: "has|未提及|异常",
        items: [{
          id, name, desc,
          status: "已取得|预期|原文未明确",        // 成果维度必填
          evidence: [{ version, locator:{ page? , start_line?, end_line? }, quote }]
        }]
      }] }

③ 提交提取 / 失败重试
POST /api/corpora/{id}/target  { doc_ids: string[], force?: boolean } → { job_id }
GET  /api/corpora/{id}/target/jobs/{job_id}  → { status, completed, total, errors:[…] }   // 必须补齐
```

**约束**：关联（`relations`）由接口返回，前端不自行配对；无可靠页码时不返回 `page`；版本不符返回明确状态，前端显示"资料已更新"。

## 11. 验收（对齐首批单条流程）

1. 知识库 → 选一份资料 → 生成四维信息 → 四分区 → 点证据 → 返回原位置，**全程可走通**。
2. 四个维度标签：**有内容可点击 / 无内容显示"未提及"**，页面**无任何完成百分比**。
3. 结构缺字段显示为**提取异常**并可重试，**不**显示成"未提及"。
4. 部分处理显示**未完成**，不计入完整覆盖统计。
5. 成果条目**必显** `已取得 / 预期 / 原文未明确` 之一。
6. 证据跳转：有可靠页码跳页，否则定位解析正文；**版本不符显示"资料已更新"**，不用旧位置打开新内容。
7. 返回后**主区筛选、选中报告、滚动位置**均保持。
8. 批量显示**真实完成份数**；单份无进度时显示"提取中"，不编造进度。
9. `npm run build` 通过；既有 `browser_library.py` / `browser_document_preview.py` / `browser_tasks.py` 无回归，并扩展上述流程场景。

> 浏览器替身通过 ≠ 抽取质量通过（§10.6）；真实 LLM 小样本语义核对另行安排。
