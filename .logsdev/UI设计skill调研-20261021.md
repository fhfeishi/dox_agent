## 结论先行

1. **这是一份可选清单，不是固定流程。** 做 UI 工作时，先看任务性质（日常改页面、审查、定新视觉方向、出演示稿、引入新组件），再从下面的清单里自行挑一个合适的 skill 或规则文件；不必全部使用，也不必按某个顺序全部走一遍。
2. **清单按从轻到重排列**：纯规则/清单文件（项目自己的 `DESIGN.md`、Vercel `web-design-guidelines`）→ Anthropic `frontend-design` → 已装的 `baoyu-design` → `ui-component-sourcing`（有前置条件）→ `ui-ux-pro-max`（最重）。能用轻的解决就不必上重的。
3. **`ui-component-sourcing` 不适合做 demo HTML，也不适合当前仓库直接使用。** 它第 0 步要求 `components.json` 存在（即项目已接入 shadcn），缺失就直接中止（"`components.json` missing -> STOP; never run `shadcn init`"）；`frontend/` 下没有 `components.json`。它只适用于"已接入 shadcn 的 React 项目里新增组件"这一种场景。
4. 现状观察：仓库已有 2 个设计 skill（`baoyu-design`、`ui-component-sourcing`），`.logsdev/owner-*-design/` 下有 30 多个设计稿 HTML。缺一份把现有 token 和组件写下来的规范文件，选 skill 前有这份文件会更省事（建议，非必须）。
5. 和记忆/PDF 方案相关、可能值得优先考虑的界面有 3 处：引用页码可点回原页、"本次任务状态"小面板、PDF 章节树（见第四节，供参考）。

## 四、可选建议与慎用项

### 可选建议（供参考，按需取用）

- 写一份 `frontend/DESIGN.md`，并在 `AGENTS.md`/`CLAUDE.md` 里提示"做 UI 前可先读它，再按第二节清单自选 skill"。约 0.5 天。
- 与记忆/PDF 方案相关的 3 处界面，可按需要考虑：①引用标注"资料·页码"可点，打开 `PdfViewer` 到对应页；②聊天侧栏加只读的"本次任务状态"（报告参数、已引用资料编号、选中章节）；③文档详情页加章节树。合计估约 2～3 天。
- 设计稿版本较多时，可以考虑定稿后把旧稿移到 archive，减少 agent 读错稿的概率（可选做法）。

### 慎用项

- 不建议为了用某个 skill 而引入 shadcn/Radix 全家桶或迁移 Next.js。
- 不在 `ui-component-sourcing` 前置条件不满足时运行它，也不用它做 demo HTML。
- ui-ux-pro-max 较重，非从零做视觉时一般用不上。
