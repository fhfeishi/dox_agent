# 资料库外置与数据分组实施方案

日期：2026-10-12。状态：实施设计，尚未修改运行代码、配置或真实数据。

采用“资料库自包含、应用状态分组、可清理缓存独立”的方向。用户明确要求：接入资料库的根目录固定为 `target_root/.knowledge`，默认值为 `dox_agent/.knowledge`。因此默认 `target_root` 是实际项目根目录，不是当前命令所在目录。

本轮仅整理本方案。下文配置变量、应用目录布局和迁移机制是实施设计，不表示功能已经存在，也未同步为项目正式需求、决策或执行记录。

## 1. 范围与替代关系

解决资料库外置、库身份和人工整理保留、应用数据分组、缓存独立清理、资料脱离 Git 分发。保留单一资料库根目录、每个直接子目录一个库、库名取目录名、现有跨库对话范围和成果七天回收规则。

当前不引入多位置注册、联网同步、多用户、源文件回收站或完整原文历史版本系统。实施本方案时，需要调整旧“所有持久数据归入 .knowledge”及 2026-10-10“资料随 Git 提交”的约定；本轮不修改这些正式记录，README 与代码中的旧布局仍是运行现状。本轮不改变 Git 跟踪或改写历史。

## 3. 根目录与配置契约

### 3.1 资料库位置

拟新增唯一用户配置 `TARGET_ROOT`：

```text
target_root = 未设置 TARGET_ROOT 时取实际项目根目录，否则取配置路径
corpora_root = target_root / ".knowledge"
```

| 场景 | TARGET_ROOT | 实际资料库根目录 |
|---|---|---|
| 默认 | 未设置 | <项目根目录>/.knowledge |
| Windows 外置 | D:/research | D:/research/.knowledge |
| Windows 磁盘根 | D:/ | D:/.knowledge |
| WSL 访问 D 盘 | /mnt/d/research | /mnt/d/research/.knowledge |

TARGET_ROOT 表示 `.knowledge` 的父目录。误填以 `.knowledge` 结尾的路径时提示修正，不静默产生双层目录。相对路径按项目根目录解析，显示最终绝对位置，不受启动工作目录影响。Windows 与 WSL 使用各自可访问的路径，不做字符串猜测转换。

首次初始化可显式创建空根目录；关联已有资料时验证目录存在且可读写。目录不可访问或已登记库离线时保留登记并显示原因，不自动回落到默认路径或创建同名空库。启动不自动解析全库或调用模型。

### 3.2 应用数据位置

建议新增 `APP_DATA_ROOT`，默认 `<项目根目录>/.dox-agent`。它不随 TARGET_ROOT 自动变化：只搬资料库时，对话、成果仍留在原应用目录；需要一起外置时显式配置。

```dotenv
# 拟议配置，当前版本尚不支持
TARGET_ROOT=D:/research
APP_DATA_ROOT=D:/dox-data
```

应用配置、持久状态、缓存从 APP_DATA_ROOT 派生为 `config/`、`state/`、`.cached/`，不为每个子目录增加变量。密钥沿用现有环境配置，不写入库元信息。

新版本只读取新契约；旧 CORPORA_ROOT、STATE_DIR 和 CORPORA 覆盖由离线迁移转换。旧 CORPORA_ROOT 以 `.knowledge` 结尾时可给出父目录转换建议，其他目录名须明确选择新位置。发现未迁移旧配置时明确报错，不静默忽略或同时维护新旧布局。内部可保留派生 corpora_root/state_dir 属性，但不保留两套外部配置来源。

首批通过本机 `.env` 设置并重启，界面显示路径与可用状态。热切换或浏览器任意目录选择不作为首批前置。一个数据集只允许一个服务实例写入；服务与迁移工具须有共同的独占写入约束。

## 4. 目标目录与职责

```text
target_root/
└─ .knowledge/
   └─ <库目录名>/
      ├─ corpus.json
      ├─ source/
      ├─ parsed/
      ├─ datadb/knowledge.sqlite3
      ├─ vectordb/
      ├─ target/
      └─ analysis/
         ├─ hierarchy.json
         ├─ lineage.json
         ├─ lineage_frame.json
         ├─ lineage_blanks.json
         ├─ topic_summaries.json
         └─ curation.sqlite3

APP_DATA_ROOT/
├─ config/
│  ├─ libraries.json
│  └─ library-groups.sqlite3
├─ state/
│  ├─ chat-history/workspace.sqlite3
│  ├─ runs/runs.sqlite3
│  ├─ artifacts/artifacts.sqlite3
│  ├─ review/                  # 原审查数据库、上传与报告
│  ├─ templates/               # 自定义任务、模板、Prompt/Skill 数据库
│  └─ web-snapshots/web_snapshots.sqlite3
└─ .cached/
   ├─ indexes/                 # 纯派生项目与相似度索引
   ├─ results-cache/           # 实际需要时保存的可再生成结果
   ├─ exports/
   ├─ previews/
   └─ tmp/
```

目录按需创建，不预建空数据库或凭空增加缓存功能。`chat-history` 是持久记录，不采用 chat-histore 拼写，也不放入 .cached。results-cache 不存用户成果正文、编辑版本或唯一可恢复的生成内容。

库级框架、空白节点属于维护信息；层级、谱系、主题综合属于生成结果，都随库迁移和备份。保留 JSON 格式，只收拢路径，不同时重写业务 schema。curation.sqlite3 保存人工主题归并与撤销记录，保留原 ID 和关联。

回收站继续是 artifacts.sqlite3 内的生命周期，不创建 `recycle-bin/` 正文副本。未来如增加文件回收，另行定义范围与还原规则；本次不扩大到源资料或审查材料。

## 5. 库身份、登记与资源定位

| 信息 | 权威位置 | 规则 |
|---|---|---|
| 库 ID、结构版本、领域、说明 | corpus.json | 旧库沿用 ID，新库 ID 与路径无关；名称取目录名 |
| 库 ID 对应的根目录内相对位置、缺失登记 | config/libraries.json | 不复制库领域等元信息；存在库可由身份文件重新登记 |
| 展示分组、顺序与 revision | config/library-groups.sqlite3 | 保留 GroupStore 的冲突检查语义 |
| 文档 ID、source 内相对路径、内容版本 | datadb/knowledge.sqlite3 | 不以绝对位置作为身份 |
| 人工主题归并 | analysis/curation.sqlite3 | 随所属库移动，与派生索引分开 |

身份与登记 JSON 带 schema_version，使用原子替换；精确字段在实现时由一处类型定义约束。登记缺失不等于删除库或解除旧会话绑定。

发现没有身份文件的旧库时，先依据旧注册表迁移 ID；关系不明时报告具体冲突。外部改名后依据唯一库 ID 重新定位，不猜名称相似关系。两个目录声明同一 ID 时阻止歧义库写入，不自动重编号副本，因为内部及历史引用仍有关联。

引用保持 `corpus_id + doc_id + version`。原文由当前库位置加 source 内相对路径定位；解析图片由已保存的库内解析位置定位。统一解析需验证最终路径仍在对应库允许目录内，拒绝路径穿越与链接逃逸。

迁移保留既有文档 ID、版本与文件清单。新文档 ID 一次生成并持久化，原文件替换沿用身份并更新版本；不重编号旧数据。旧绝对路径依文件清单和显式旧根映射转换，无法定位则保留并列出问题，不猜测覆盖。迁移不是重新导入。

文件接口、报告图片、审查上传及其他 payload 中的绝对路径都需盘点，不能只改 docs.origin。转换完成后删除按根目录名称猜测映射的旧运行逻辑，不保留双读链路。

## 6. 历史与缓存清理

| 数据 | 保留原则 |
|---|---|
| source、身份清单、库元信息、人工整理 | 默认持久保存，不参与缓存清理 |
| parsed、target、库级生成结果 | 保留，不按普通缓存期限删除 |
| 会话、运行、成果、模板、审查 | 默认持久保存；删除走所属业务操作 |
| 已引用网页与外部材料快照 | 随引用依赖保留，不能仅凭年龄清除 |
| 成果回收项 | 沿用七天、还原和到期清理；保留最小删除标记防回补 |
| 临时导出、预览、中间结果 | 可显式清理；跳过使用中文件和活跃任务目录 |
| 纯派生索引、vectordb | 可显式重建，先确保人工数据分离且重建来源存在 |

首批提供分类查看位置、占用和手动清理；除既有成果回收规则外，不新增自动过期策略。缓存键区分所属对象、内容版本和生成器版本，避免源资料变化后读取旧结果。缓存清理不触碰用户指定备份。

浏览器偏好继续留在浏览器，查询缓存按业务状态失效；服务端目录分组不等于浏览器数据迁移。当前知识库更新会替换当前正文，版本标识不代表保存全部历史原文。本次保留版本核验与失效提示，不承诺完整原文历史；已有成果版本必须完整迁移。

## 7. 停写迁移与恢复

迁移为独立离线步骤，显式指定旧资料根、旧状态目录、新 TARGET_ROOT、新 APP_DATA_ROOT 和独立备份位置。启动扫描或读取页面不得偷偷搬迁。

1. **预检**：停止服务并确认无其他写入实例；核对权限、空间、重复 ID、数据库完整性和目标冲突。源目标相同时识别原位布局迁移；禁止备份或目标嵌套导致递归复制。已有不同数据不得覆盖。
2. **成组备份**：包含资料库和完整应用状态，特别是注册、会话、运行、成果、图片、输入、模板、审查及人工归并。使用一致性数据库备份；处理 WAL，不能只复制可能遗漏事务的 SQLite 主文件。
3. **准备目标**：在目标磁盘暂存位置复制和转换；跨盘采用复制、校验、切换，不假设 rename 可跨盘。保留内容、ID、版本和时间信息；迁移身份、分组、人工归并、分析 JSON 及资源路径。
4. **校验**：比对文件和成果正文哈希、记录与版本数量、引用、图片、固定模板版本、分组、归并、回收期限、删除标记。保存阶段与清单以支持重入，不重复生成身份或重置期限。
5. **统一切换**：全部检查通过后更新配置并启动新版本，仅启用新读写路径。目标未完成迁移则拒绝启动。旧数据保留为离线备份，不立即删除。
6. **恢复**：切换前失败可继续用完整旧集合；切换后回退先停写、保留新产生的数据再成组恢复，不单独替换一个数据库。恢复旧备份会恢复当时的回收状态，不承诺删除穿透备份。

新迁移必须识别是否已完成既有 [成果迁移](../../src/artifact_migration.py)。旧成果结构尚未升级时先完成并验证该迁移，再执行布局转换，不复用不同迁移的完成标记。

## 8. Git 与资料交付

实施后 Git 仅保存源码、内置模板、配置示例、文档及小型测试数据；用户资料、登记、状态、缓存不跟踪。默认项目内 `.knowledge/` 和 `.dox-agent/` 整体忽略，外置目录不属于仓库。

已跟踪数据先备份再停止跟踪，本机文件保留；其他工作副本拉取前也要备份，版本控制删除可能移除其受跟踪数据。停止跟踪不会清除 Git 历史或立即缩小 clone；历史清理另行安排，本次不执行。

新 clone 默认空资料环境，通过初始化或恢复资料包使用。资料包包含身份、源文件、解析结果、数据库、提取和库级整理，可省略可重建向量索引；会话成果单独备份。实施时同步 README 和资料管理说明，移除“clone 自带全部资料”的旧承诺。

## 9. 实施批次

| 批次 | 工作 | 交付条件 |
|---|---|---|
| A：路径与身份 | 根目录派生、集中路径定义、库身份登记、文档相对定位 | 默认及外置目录身份与引用不变；错误配置明确失败 |
| B：数据分组 | 会话与分组、人工归并与索引分离；模板依赖显式接线；分析与审查路径收拢 | 原有会话、成果、模板、审查和人工整理能回读 |
| C：迁移闭环 | 停写备份、暂存转换、校验、重入、切换和恢复 | 完成下一节迁移旅程后才切换真实数据 |
| D：清理与交付 | 分类查看及缓存清理、Git 跟踪、启动说明和文档更新 | 不误删持久数据，回收规则不变，空库首次启动可用 |

A–C 构成一个完整切换版本，不能发布新路径已生效但旧数据无迁移入口的中间状态。后续若增加图形化根目录设置，复用同一预检与切换机制。

代码入口除 §2 外，还包括 [report_figures.py](../../src/report_figures.py)、[project_similarity.py](../../src/project_similarity.py)、hierarchy、lineage、topic_summary，以及启动脚本、CLI 和测试中的旧路径。只收拢实际需要的路径，不新增通用存储框架。

## 10. 最小验收与证据边界

优先扩展现有端到端旅程，不为每个目录增加字符串断言。新增一条整体布局迁移旅程，因为既有成果迁移不覆盖资料库及应用目录搬迁；具体入口在实施前确定。下表是待验证条件，不是已通过结果。

| 旅程 | 区分的真实失败 |
|---|---|
| 新增整体迁移旅程：旧库含对话、成果版本、回收项、模板、分组和归并，迁移后重启 | 只搬文件却丢 ID、哈希、版本、引用、图片、人工记录 |
| 同一旅程覆盖默认路径、外置路径、空库、目录不可访问、重复库 ID | 双层 .knowledge、静默回落、身份猜测、启动误触模型 |
| 同一旅程在准备和切换边界中断重入，目标已有冲突数据 | 重复迁移、覆盖、提前切换、无法成组恢复 |
| 扩展 [browser_document_preview.py](../../tests/browser_document_preview.py) 与 [browser_target_facets.py](../../tests/browser_target_facets.py) 的相关路径 | 搬迁后原文或四维引用失效、根外路径可访问 |
| 复用 [test_workspace.py](../../tests/test_workspace.py)、[test_artifacts.py](../../tests/test_artifacts.py)、[browser_artifacts_live.py](../../tests/browser_artifacts_live.py) | 会话/成果编辑导出失效、回收期限变化、旧请求回补、清缓存误删 |
| 复用 [test_review_flows.py](../../tests/test_review_flows.py) 的存储链路 | 审查材料、旧记录或导出仍依赖旧绝对路径 |

Windows 与 WSL 至少各完成一次配置解析和原文回读，不以一端通过推断另一端通过，不同时写同一数据库。开发时只运行直接相关的最小旅程，集成收尾按项目验证规则执行并记录实际范围。

本轮仅交付本方案。未执行代码测试、真实迁移、容量盘点、清理或 Git 数据移除；上线前须取得上述行为证据。
