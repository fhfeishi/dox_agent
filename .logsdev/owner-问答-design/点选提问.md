# 点选提问改版：浮层 + 更多可选词 + 时间维度（2026-10-21，query 2026-1021）

反馈原话：对话工作台里「点选提问弹出的卡片、打开关闭功能很差劲」，可选词要更多，并加时间（3-5 年、5-10 年、15 年内），时间要真的带动检索。

## 1. 卡片改为浮层

原来它是输入框上方的一块**内联面板**：展开时把对话区和输入框一起顶上去，页面上所有东西都跳一下；出口只有右上角一个 12px 的「收起」。

现在：

| 项 | 做法 | 为什么 |
|---|---|---|
| 定位 | 绝对定位在输入列上方 10px（`bottom-[calc(100%+10px)]`），宽 818px 与输入框同宽 | 打开时页面不重排——验收时记录了 textarea 的 y 坐标，开合前后都是 770 |
| 入口 | 工具条「点选提问」按钮带清单图标，展开时浅蓝底 + `aria-expanded` / `aria-controls` | 入口和标题同名、状态可见，不再"点一次消失、再找按钮" |
| 关闭 | ① 点面板外任意处 ② Esc ③ 面板右上 ✕ ④ 工具条按钮再点一次 ⑤ 生成成功后自动关 | 四条手动的路径覆盖鼠标、键盘与按钮，任一都能关 |
| 动效 | 200ms 从下往上 10px + 轻微缩放，`prefers-reduced-motion` 下全局降级 | 说明它从输入框长出来，而不是凭空出现 |
| 高度 | `max-h-[min(64vh,432px)]`，内容区滚动，头尾固定 | 小屏也不会顶到页外 |

**踩到一个真实 bug**：只按「点外面就关」写时，工具条按钮永远失效——React 在同一个 click 里先执行按钮的 onClick（打开），随后把新注册的 document 监听刷入，同一次点击冒泡到 document 时又把面板关掉。修法是让外部点击忽略带 `aria-controls="quick-ask-panel"` 的元素，把开关交给按钮本身。

## 2. 可选词更多

- **附带问题** 5 → 10 条，按"现状 → 缺口 → 主体与投入 → 对标"排；最多同时选 3 条，其余置灰并说明原因（再多会把生成的问题撑过 150 字，模型只能漏写）。
- **关注场景** 超过 8 个时折叠成「还有 N 个」，不把面板撑成一面墙。
- **关注要素** 仍是五项：技术谱系 / 场景 / 问题 / 关键技术 / 成果。这五项是 `compose_question.md` 与四维抽取共同的口径，加词会让问题与检索对不上，所以没动。

## 3. 时间维度

| 选项 | 年份区间 | 语义 |
|---|---|---|
| 不限时间 | — | 全部立项年份 |
| 近 3 年 | 2024—2026 | 最近三年 |
| 近 3–5 年 | 2021—2026 | 最近三到五年（取外沿，含三年窗口） |
| 近 5–10 年 | 2016—2026 | 最近五到十年 |
| 15 年内 | 2011—2026 | 十五年内 |

年份由 `new Date().getFullYear()` 计算，跨年自动前移；chip 的 `title` 与行内说明都写出具体区间，避免"近 3–5 年"到底指哪几年说不清。

## 4. 时间如何带动检索

链路是三段，缺一段就只是句人话：

1. **写进问题**：`/api/compose-question` 新增 `period`（`YYYY—YYYY`，校验起止与顺序）。模型输入多一行「时间范围：2021—2026」；若模型把它改写成"近五年"，服务端会在句尾补回原区间，保证字面年份一定在问题里。
2. **检索筛选**：`select_reports` 本来就从问题里识别 `起—止` 作为项目年份条件（按文件名起止年与窗口相交），所以不需要新接口——年份在问题里，筛选自然生效。
3. **空窗放宽**：窗口内一个项目都没有时，原先直接返回「没有匹配的报告」，对"项目都结束在 2023 年"的库等于死路。现在改为：放宽到全部年份继续检索，`year_relaxed=True`、`year_window=None`，检索过程显示「所选时间范围内没有项目，已按全部年份检索」，回答提示词也要求开头讲明没做时间筛选——不放宽也不假装筛过。

专项报告（task4）走 `build_report_brief`，同样识别这段年份，报告的年份区间会跟着走。

## 6. 已知取舍

- 空会话仍自动展开一次（原来如此），所以首屏会盖住欢迎语；换来的是引导浮层（CoachMarks）有实体可指。
- 附带问题硬上限 3：更多选择会让生成的问题超长、模型漏写，宁可提示"先取消一项"。
- 时间按**项目起止年份**筛，不是成果发表年；文件名没有年份的资料不参与筛选（窗口放宽后仍会被检索）。

## 7. 生成问题用上已有信息（2026-10-22，query 2026-1021 1619）

| 情况 | 以前 | 现在 |
|---|---|---|
| 输入框里已有文字 | 不发送，生成后被覆盖 | 作为问题核心发送；面板顶部显示“已输入” |
| 点得少、没输入（要素 + 附带问题 ≤ 2） | 生成泛泛的问题 | 从本库已抽取的场景、未解决问题和技术体系里挑 1–2 个名称收窄问题；面板写明补充了哪些名称 |
| 再点一次 | 同样的条件给出差不多的句子 | 带上之前的版本，要求换对象、维度或层次；换一批库内名称，温度调高 |
| 生成后 | 直接填入输入框并关闭 | 先在面板里显示：可“换一个角度”，‹ › 翻看之前的版本，选好后“填入输入框” |
| 模型把年份改写成“近五年” | 第 4 节写的“服务端补回”实际没有实现 | 由服务端补回 `（2021—2026）` |

由面板填进输入框的问题，下次打开面板时不算作“已输入”，而是作为之前的版本，避免拿上一轮生成的问题当成用户自己写的内容。
