# 对话知识库交互优化方案

日期：2026-09-30。交付范围：交互与技术方案，未改产品代码，未运行界面验收。

核心调整：**输入框上方以本次对话选中的知识库为主角，逐个高亮；保留“＋管理知识库”；上传目标只在添加资料的流程中明确呈现，不决定对话范围或高亮。** 页面标题、管理面板、资料选择、历史轮次与导出采用一致的范围语义。

## 1. 要求与方案边界

用户本次明确要求：

- 选择两个知识库对话时，上方高亮这两个库，不能只显示上传目标库。
- 上传目标可以与这两个对话库完全无关，不能因“锁定”上传目标而强制纳入对话。
- “＋管理知识库”入口必须保留。
- 扩展梳理交互逻辑、状态、显示与技术细节，并交付到 `.logsdev/`。

上述要求同步到 [PROJECT.md](PROJECT.md) 的知识库需求。以下布局、即时选择、上传交互及实现安排属于推荐方案，未作为已实现功能或已确认的长期决定。截图仅作为现状证据，图中文字不是额外工作指令。

沿用现有约束：新对话按目录升序选择首个存在库；对话范围为 1–6 库；浏览不改变检索范围；专项报告正文目前只能选择一个库生成；限定资料最多 20 份。不在本轮方案中扩展跨库报告引擎、分组模型或另建状态管理框架。

## 2. 当前问题与代码依据

核对基线：Git `4f49593`，读取日期 2026-09-30。工作区原有 `.logsdev/query.md` 未提交修改，本轮保留原样。

| 已核对的现状 | 导致的理解问题 | 代码定位 |

## 3. 推荐布局

### 3.1 输入框上方

示意使用简称便于阅读；产品中保留真实库名称，长名可截断并通过焦点/详情显示全名。

```text
对话知识库  [✓ AI与医疗  ×] [✓ AI与农业  ×]  [＋ 管理知识库]  2/6
专项报告 · 所选库全部已入库资料 · 本地资料

┌──────────────────────────────────────────────────────────────┐
│ 描述报告需求：领域、年份范围、模板……                            │
│ [＋]  [资料范围：全部]                           [配置] [发送] │
└──────────────────────────────────────────────────────────────┘
```

- 一个选中库对应一个紫色浅底 chip；选中态增加勾选/文字语义，不只靠颜色。上传目标 C 不出现在 A、B 的对话 chip 中。
- 名称是主要信息，不默认堆叠每库文档数；计数放入详情或管理面板，写“已入库 517 份”，不展示无单位数字。样例数字来自截图，不表示本次重新统计。
- 点击 chip 名称打开管理面板并定位对应项；点击独立的“移除”按钮才修改范围，避免点击名称误删除。不要用嵌套按钮。
- 最后一个正常选中库的移除按钮禁用，并给出“至少保留 1 个知识库”；失效旧范围允许先加入可用库再移除失效项。
- 1–6 个 chip 均可查看。常规宽度自动换行，长名限制单个宽度；窄屏标签区可纵向滚动，“＋管理知识库”置于独立常驻工具行，不放进溢出菜单。
- 不再附加一串重复的“当前对话：A、B…”。`2/6` 表示已选库数/上限，不与总库数混用。

### 3.2 配置摘要与标题栏

- 上方摘要显示任务、资料模式、网络资料状态；模型、模板与输出格式收入可展开的“配置”。展开后仍可核对完整有效值，不删除能力。
- “资料范围：全部”明确解释为“所选知识库中全部已入库资料”，不代表全站库、所有源文件或全文都被模型阅读。
- 限定模式显示“指定 8 份资料”；空限定显示“指定 0 份 · 请重新选择”，禁止以长度为 0 显示“全部”。
- 网络摘要按已确认网页快照显示“本地资料 + 2 个网页快照”；无快照显示“本地资料”。网络搜索配置可用不等于正在使用网络。
- 标题栏单库显示“对话库：A”，多库显示“对话库：2 个”，点击查看完整名称；不再取上传目标。历史每轮的范围仍单独保留。
- 专项报告模式在报告卡片显式说明“本轮对话使用 2 库；报告正文使用 1 库，待选择”。选择 A 后显示“报告库：A”，不能默认拿上传目标 C 生成。

### 3.3 “＋管理知识库”面板

入口不改名、不删除。面板标题为“管理对话知识库”，副标题“已选 2/6，修改对后续新提问生效”。顶部放搜索与已选区域，下方是可滚动的候选列表，底部保留“打开知识库管理”和“新建知识库”。

```text
管理对话知识库                              已选 2/6   [关闭]
[搜索知识库                                             ]
已选：[AI与医疗 ×] [AI与农业 ×]

[✓] AI与医疗     可检索 · 已入库 517 份     [详情] [仅用此库]
[✓] AI与农业     可检索 · 已入库 13 份      [详情] [仅用此库]
[ ] AI与材料     可检索 · 已入库 14 份      [详情] [仅用此库]

[打开知识库管理] [新建知识库]
```

整行主区域和复选框均只切换对话选择；勾选项决定行高亮。详情、仅用此库是独立按钮，阻止行事件传播。面板不再通过整行点击设置上传目标，也不再以“上传目标”作为行选中标志。

采用即时生效：符合现有方式，不增加“应用”步骤；展开后逐次操作均与上方 chip 同步。关闭、点外部、Escape 均只收起面板，不撤销已成功保存的选择。保存中和失败有明确状态，详见第 6 节。

搜索只过滤候选，不改变已选范围；顶部已选区域始终可见，搜索不到已选库不代表它被取消。无结果给清空搜索操作。选满 6 库时未选项不能加入，但已选项仍可移除；禁用原因显示在面板中，不仅放 hover 提示。

“仅用此库”对已经选中的库也显示（当前恰为单库时禁用），一次把集合替换为该库；不发消息、不创建新会话、不切换上传目标。涉及限定资料减少时按第 5 节提示，不引入每次勾选的确认框。

## 4. 四类状态的职责

下表为目标语义；复用现有结构并收敛调用方，不新增四套持久化存储。

| 状态 | 意义及有效来源 | 可以改变它的动作 | 不能影响什么 |
| --- | --- | --- | --- |
| 对话库集合 | 会话 `corpusIds`；发送使用显式 `corpus_ids` | 勾选、移除、仅用此库、明确发起新任务、恢复会话 | 不随浏览或上传切换；不重写历史轮次 |
| 浏览位置 | 当前库路由/现有 `corpusId` 的浏览用途 | 打开详情、本地文档窗口切库 | 不加入检索、不替换对话范围 |
| 上传目标 | 上传面板中显式选择的单库；开始上传后该批次固定 | 打开添加资料并选择目标库 | 不要求属于对话集合、不自动参与回答 |
| 本轮运行范围 | 发送时冻结请求，回读服务端有效范围 | 发送、原范围重试/重新生成 | 不受后续界面状态改变；不改来源归属 |

资料过滤是对话库集合上的附加限制；报告库是报告卡片上的单库参数，不是第五种通用“当前库”。网页快照按现有本轮资源记录独立管理。

只允许在新会话初始化时沿用“首库”规则；恢复 A+B 的旧会话，即使浏览或上传目标是 C，也必须保持 A+B。旧范围缺失/超过上限时保留其身份并提示修复，不静默替换为首库。未知 ID 显示“知识库不可用（ID）”，不要写成“未选择”。

## 5. 操作联动与资料范围

| 用户操作 | 推荐结果 |
| --- | --- |
| A → 勾选 B | 显示 A、B 两个 chip；全部模式覆盖 A+B，限定模式保持原指定文档，提示“新增库中的资料尚未选入” |
| A+B → 取消 B | 显示 A；全部模式只覆盖 A；限定模式去除 B 的文档并说明数量 |
| A+B → 仅用 C | 显示 C；允许 C 不同于上传目标；过滤限定资料，可能进入空限定阻断状态 |
| 浏览 C 或在 C 中上传 | A+B 对话范围保持；完成后刷新 C 的计数与文档，不自动更改检索范围 |
| 上传到 A（A 在对话范围内） | 全部模式下完成入库后供后续新请求使用；限定模式不自动选中新文件；已运行回答不变化 |
| 从知识库页“与此库对话” | 保持已有独立新会话行为，显示新会话的单库；不在后台改旧会话 |
| 修改范围后继续提问 | 当前会话后续轮次使用新范围；显示短提示“下一次提问将使用 A、B”，历史显示原范围 |
| 重新生成、改后重发、创建分支 | 默认使用被操作轮次的原范围快照；明确显示该范围，不能悄悄改用输入框新范围 |

必须区分 `allowed_doc_ids === null`（全部）、非空数组（限定）、空数组（限定已空）。同一规则用于 chip 摘要、资料选择器、发送按钮与报告预检。

移除 B 的 3 份资料后就地显示“已移除 B 的 3 份指定资料，剩余 5 份”。若剩余 0 份，提供“重新选择资料”和“使用所选库全部资料”两个操作；只有用户点击后才设为全部。文件被删除或版本失效也按实际原因提示，不静默补选。

资料请求返回较慢时，只能更新与请求的库集合相匹配的数据。筛选列表未就绪时不能依靠空数组清理持久选项；使用可信的文档归属信息或待核对状态，防止切库竞态误删限定资料。

保留跨库同文档 ID 的现有限制：显示“文档归属不唯一，暂不能限定选择”，可使用全部模式；不伪造唯一归属。本轮不扩展复合文档标识 API。报告选择 A 时，其文档仍须来自被操作轮次的限定集合与 A 的交集，不拿当前输入框新范围替代。

## 6. 可用性、运行状态与失败恢复

| 状态 | 显示 | 操作规则 |
| --- | --- | --- |
| 列表加载中 | 保留可回读的会话范围，标“正在核对知识库” | 管理入口保留，打开显示加载；禁止发送；不当作空库 |
| 列表读取失败/断网 | 错误与重试；已有范围标“暂未核对” | 保留草稿与旧范围，不自动保存空选择 |
| 尚无库 | “尚无知识库”与新建/刷新 | 管理入口保留；不能发送 |
| 空库/未就绪 | chip 状态与“暂无已入库资料”，提供详情、添加、刷新 | 可选中；是否发送沿用服务端可用性规则，不悄悄剔除 |
| 导入中/部分失败 | “导入中”或“部分文件失败”，另列已有可检索数 | 不把 job 状态直接等同检索不可用；按现有 preparation 与服务端判断 |
| 目录缺失/未知库 | 保留异常 chip 和文字原因 | 阻止发送，允许修复；不强制失效库继续保留 |
| 库数 1/6 | “至少保留 1 库”/“最多选择 6 库” | 禁用对应新增/移除动作；仍可通过仅用此库替换 |
| 范围保存中 | “正在保存范围…” | 同步显示本地操作结果；序列化保存，保存完成前禁止发送 |
| 范围保存失败 | “范围未保存”，保留待保存选择与草稿 | 给重试或恢复已保存范围；不得假装刷新后会保留新范围 |
| 回答/报告生成中 | 显示“本轮使用 A、B”，与停止入口 | 冻结影响本轮配置的修改；管理入口可打开只读列表，详情浏览仍可用 |

统一发送资格：库数/目录有效、所选库可用性、资料模式、会话范围保存状态、任务/模型现有条件等，按钮提示和最终发送校验使用同一语义。已确认网页快照可配合空本地库回答的现有例外仍保留；不要由此允许未知库或目录缺失。

A 空库+B 可用时，沿用当前发送规则：无网页快照则阻止，并提供移除 A 或添加资料；不能只检索 B 却继续声称使用 A+B。有网页快照时仍显示 A 为空，不把它标成已就绪。服务端最终拒绝时呈现具体原因与修正入口。

运行开始后标题或配置摘要优先展示运行快照。停止并结束运行后恢复后续提问配置；不能把执行中的范围和下一轮范围混成一行。本轮历史范围以服务端 `effective_corpus_ids` 为准，未回读时写“请求范围”，不能提前宣称“实际检索了两个库”。

## 7. 上传目标的独立交互

- 输入框“＋”保留现有任务/资源入口；添加资料应进入明确的添加流程或现有库详情上传入口，不能把选择任务变成上传。
- 从库详情添加资料时目标固定为该详情库；从对话入口添加资料时展示目标单选，候选包含所有可用库，允许选非对话库 C。
- 对话仅选一个库时可预填该库，多库时推荐不默认选第一项，要求在上传面板中选择；记住目标若作为后续体验优化，仍必须在提交前清楚展示。
- 面板显示“保存到：C”。C 不参与本轮对话时显示“此库未用于当前对话”；给可选的“加入当前对话”动作，绝不上传后自动加入。已满 6 库或运行中时解释为何暂不能加入。
- “锁定”只用于已经开始的上传批次，避免文件分散到多个库；没有上传任务时不存在必须锁定的目标。新批次可重新选择，不影响正在执行的批次。
- 上传成功、解析/入库成功是不同阶段：分别显示，不把“文件已保存”说成“已可检索”。部分失败逐文件可定位，重试只处理失败项，不重复上传成功项。

上述上传流程是推荐细节；现有按库上传 API 可复用，不新增批量目标路由。实现时核对实际上传入口，不凭方案假定已有上传队列或附件组件。

## 8. 实现落点与删除范围

第一批先完成同一条“选两库 → 显示两库 → 浏览/上传第三库 → 发送仍使用两库”旅程，再收口历史与报告，避免只更换 chip 留下错误标题。

| 落点 | 最小调整 |
| --- | --- |
| `Composer.tsx` | 多库 chip、常驻管理入口、精简配置、资料三态显示；管理触发器纳入同一点击边界，避免点击关闭后重新打开；互斥展开面板 |
| `CorpusPicker.tsx` | 高亮来自 `selectedIds`；行点击与复选框同义；详情独立；取消上传目标高亮/标签及混用 props；更新过时注释，核对其他调用方 |
| `store.tsx` | 收敛有效范围与可用性校验；处理限定资料过滤与迟到响应；范围保存状态明确；避免多次保存乱序覆盖 |
| `workspace.ts` | 沿用会话存储，保证范围与关联选项一致保存、恢复；保存失败不伪装成功 |
| `ChatView.tsx` / `sessionExport.ts` | 标题显示对话集合；导出采用各轮快照，若轮次变更范围则显示“本会话使用过多个范围”，避免统一标为单个上传库 |
| `ScopeSelector.tsx` / `useDocuments.ts` | 显示全部/限定/空限定；归属不唯一如实提示；资料查询按集合隔离 |
| `MessageView.tsx` | 保留单库报告选择并增加边界说明；重新生成/分支入口显示被操作轮次的范围 |
| 库详情及实际上传入口 | 分离浏览与上传目标，只让显式加入动作改变对话；提交时固定目标库 |

请求与数据约束：聊天仍使用 `corpus_ids`，报告仍使用其现有单库参数，上传仍调用按库文件接口。不把上传目标写入聊天请求集合。现有会话 `corpus_id` 仍承担历史/浏览恢复用途，不直接删持久字段；也不能用它覆盖已存在的 `corpus_ids`。先清理误用调用方，不新增兼容开关或全局状态库。

显示集合由稳定 ID 映射名称，不按名称绑定；按用户选择顺序展示，刷新不重排。不同选择操作统一去重。后端有效范围回读与版本/来源绑定沿用已有契约，不从 chip 文本反推请求参数。

快速勾选时允许连续本地选择，但持久化必须串行提交并确保最后一次成功状态对应最终集合与资料选项；中途失败保留最后已保存快照和未保存差异。关闭面板不丢保存状态。为保存定义待处理状态即可，不建设通用事件总线或离线队列。
