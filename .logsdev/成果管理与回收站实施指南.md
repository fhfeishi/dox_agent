# 成果管理与回收站实施指南

日期：2026-09-30  
状态：已实施并完成集成验证（2026-09-30）；证据与验证边界见 [ITERATION.md](ITERATION.md) §16.49。

本指南解决成果删除、回收站、还原和到期清理，同时明确统一管理目录与模板入口的关系。用户明确要求可删除成果、删除后暂存、保留一段时间后彻底删除且支持还原；本指南采用 **7×24 小时**作为首版保留期。目录布局、历史数据收敛与模板边界是根据当前项目设计提出的实施方案。

## 1. 交付目标

用户可以从成果卡片或详情将一个成果移入回收站，7 天内查看和还原，也可明确选择提前彻底删除。正常成果列表、会话报告入口、旧报告地址和导出接口遵守相同状态，不能出现“卡片消失但另一个接口仍能编辑、导出或自动重建”的情况。

还原必须保留原 ID、全部版本、当前版本、标题、引用、图片、来源运行和会话关联。到期后成果正文、版本和独占附件从应用管理的存储中删除，回收站不再提供恢复。原知识库资料与独立聊天记录不随成果删除。

统一管理区增加模板入口，但模板保持原有发布、固定版本和归档规则；首版不把模板当成报告成果套用 7 天销毁。已发布任务依赖模板版本，未经依赖处理直接销毁模板会破坏任务执行。该边界见第 4 节。

## 3. 目录与存储选型

### 3.1 同一标准下的选择

| 方案 | 能解决的问题 | 代价与主要失败方式 |
| --- | --- | --- |
| 沿用 STATE_DIR，增加 artifacts 子目录，数据库管理正文和回收站 | 复用现有版本、事务、图片与部署配置；可统一目录和入口 | 需要一次迁移，但不需要文件与数据库双向同步 |
| 仓库根独立 .artifacts，正文逐份落盘，数据库做索引 | 用户直接浏览 Markdown 和物理回收目录 | 改变 STATE_DIR 和备份契约；移动目录与 SQLite 提交不能一起原子完成，容易正文和索引不一致 |
| 保留现有多个数据库，仅给卡片做逻辑删除 | 局部改动少 | 无法彻底处理历史回读、正文副本及回补，不能满足完整删除 |

**采用第一方案作为推荐实施路径。** 项目本来以 SQLite 管理版本、引用与图片；这里没有文件优先编辑的实际要求，不新增双向同步或正文镜像。

### 3.2 推荐布局

~~~text
<STATE_DIR>/
  workspace.sqlite3
  runs.sqlite3
  custom_tasks.sqlite3
  web_snapshots.sqlite3
  prompt_skills.sqlite3
  artifacts/
    artifacts.sqlite3
    templates.sqlite3
  review/
    ...形式审查独立材料和数据库
~~~

默认实际路径为 dox_agent/.knowledge/.state/artifacts/，满足本地隐藏目录统一管理；自定义 STATE_DIR 时整个目录随配置移动。

- artifacts.sqlite3 是成果元数据、版本、引用、报告参数、图片和回收站状态的唯一写入来源。
- templates.sqlite3 迁自 custom_templates.sqlite3，只改变路径，保留模板数据契约。
- 内置模板继续由 src/templates/*.md 随源码发布，不拷贝成另一套可编辑模板。
- 回收站在同一成果数据库内表示，不创建第二个正文数据库，不在删除时搬运正文文件。
- 下载的 Markdown/DOCX/ZIP 是用户导出副本，不作为数据库回写来源。
- 现有运行数据库不搬入成果目录。迁移后备份契约须包含整个 artifacts 子目录及其他应用状态。
- 新目录沿用本地状态的 Git 忽略规则，不把数据库、附件或运行导出新增提交到 Git。

首版不增加文件夹监听、Markdown 外部编辑、自动导出镜像或额外存储后端。

## 4. 产品对象和删除范围

| 对象 | 成果管理中的处理 | 删除影响 |
| --- | --- | --- |
| 专项报告 | 正常成果、删除、回收站、还原、永久删除 | 包含全部成果版本、报告参数、引用和图片 |
| 回答快照 | 同样使用成果生命周期 | 删除保存的快照，不删除独立的原聊天回答 |
| 失败成果或草稿 | 可以移入回收站 | 保留失败说明和已有版本，允许原样还原 |
| 正在生成的成果 | 显示生成状态，删除返回冲突 | 用户先停止任务，待运行结束后删除，避免后台再次写回 |
| 自定义输出模板 | 模板页管理、沿用发布/归档/还原 | 不进入成果的 7 天回收站，不删除任务绑定的固定版本 |
| 内置模板 | 浏览及复制为自定义模板 | 不提供删除源码内置模板操作 |
| 形式审查报告 | 保持 review 模块原有归属 | 该模块尚未映射为 Artifact，不隐式纳入本轮删除 |

“统一管理”指入口和本地状态目录统一，不等于所有对象必须采用相同状态机。成果删除不级联删除知识库、来源文档、任务、模板、Prompt/Skill、运行记录或会话。

永久删除的承诺限定于应用管理的该成果副本。用户原聊天回答、已下载文件、Git 中既有资料及离线备份是独立数据；本轮不做全盘安全擦除。专项报告在会话中的嵌入副本则应在迁移时转为 ID 引用，不能以这条边界为理由保留第二份受管理报告正文。

## 5. 生命周期与 7 天语义

正常成果 → 移入回收站 → 还原为正常成果，或到期/手动彻底删除。

业务状态 status 继续表达 draft、generating、completed、failed。删除状态与业务状态分离，不把 draft 改成 deleted，也不为了还原猜测原业务状态。

推荐数据：

| 字段 | 语义 |
| --- | --- |
| trashed_at | UTC 删除时间；空表示正常 |
| purge_after | trashed_at + 7×24 小时；正常时为空 |
| revision | 元数据及版本变动的并发校验号，所有成果修改递增 |
| report_id | 报告地址对应的固定身份；非报告为空 |
| lifecycle | API 根据删除时间计算 active / trashed，不另外存一份容易冲突的状态 |

超过期限的正文不得再读取或还原，即使物理清理因服务未启动而暂未执行。永久删除后只保留最小删除标记，API 以 purged 表达结果，不保留原成果正文或完整元数据。

规则：

1. 7 天从成功移入回收站的事务提交时间开始，采用服务端 UTC，UI 用用户本地时间展示准确到期时间。
2. 重复删除已在回收站的成果不重置计时。
3. 还原后清除删除时间；之后重新删除才开始新的 7 天周期。
4. 到期判断使用 now >= purge_after；恰好到期不能还原，刷新回收站显示清理结果。
5. 暂停服务期间没有代码在运行，不能承诺届时物理删除。服务启动时先清理，运行期间每小时清理一次；列表、详情及修改入口始终执行到期校验。
6. 页面显示“7 天后不可恢复；服务运行时自动清理，关闭期间将在下次启动时清理”，不能显示并不可靠的倒计时任务承诺。
7. 保留期首版固定为 7 天，不新增配置 UI；已有回收项使用记录的到期时间，后续调整策略不能静默改旧记录期限。

## 6. 正文唯一来源、历史地址和防回补

### 6.1 一次迁移后删除旧数据路径

实施时将 reports.sqlite3 中的报告迁入 ArtifactStore：

- 已有对应 Artifact 的报告保留既有成果 ID、当前版本和用户修订。
- 旧 ReportStore 的初始正文若与现有版本不同，保留为可追溯的历史版本，不能覆盖用户修订；先核对来源、时间、图片和引用。
- 尚未成为 Artifact 的历史报告建立固定映射；没有 run_id 的历史报告也可删除和还原，run_available 仍为 false，不能伪造来源核验。
- 迁移保存 report_id、原生成参数、原 created_at、来源库和来源运行。历史未记录字段仍为未记录。
- 导入顺序和 ID 映射必须可重入，不能重跑产生第二张卡片。
- 单独记录生成时的 generated_version，供报告地址和会话显式读取初始成果；不要用当前用户编辑版本冒充初始生成输出。迁移补存初始正文时版本号按 MAX(version)+1 分配，保持原 current_version 指针；后续正常新版本也按最大版本号分配，避免覆盖补存历史版本。
- 迁移以原有附件可用性为基线；原来缺失的图片保留缺失说明及原 Markdown，不通过删掉引用或重新提取伪造迁移成功。新增丢失的附件属于迁移失败，不能切换。
- 迁移完成后移除 ReportStore 的运行时读写、legacy 列表合并和从旧正文回补的分支。reports.py 保留生成与范围核对功能，其存储类退出运行路径。
- /api/reports/{report_id}、旧 report: 地址仍可作为 ID 解析入口，最终指向同一 ArtifactStore 并经过同一生命周期校验。这是地址映射，不是旧正文存储回退。
- /api/reports 创建接口仍用于专项报告流程；生成开始时建立 generating 成果，成功时在同一实体写版本，失败时标记 failed，避免完成后再建立第二份正文。

### 6.2 还原与永久删除之后的幂等行为

使用 artifacts.sqlite3 内的最小删除标记表，保留 artifact_id、report_id、report_run_id、purged_at；无正文、图片、引用、用户标题或生成参数。

- 自动修复、旧地址读回和同 run_id 的报告重试不能复活 trashed / purged 成果。
- 回收期内相同报告运行请求返回成果已删除及可还原信息；只有显式还原操作能恢复。
- 永久删除后的旧报告运行请求返回不可恢复，用户明确重新生成时创建新 run_id、新成果。
- 删除标记不能按 7 天再自动销毁，否则未来旧请求又能回补。
- 回答快照允许用户从原聊天明确再次保存为新成果；禁止的是后台悄悄恢复原 ID，不是禁止用户重新保存独立聊天回答。

## 7. 会话与前端缓存

专项报告的会话结构改为仅保存 report_id / artifact_id 和必要的引用身份，不再持久保存报告 markdown、图片或全套 ReportInfo。正文按成果 API 读取。

迁移所有会话分支和历史 attempts 中的嵌入报告，保留问题、运行过程和身份引用。前端缓存及 localStorage 的旧会话正文也需一次转换；服务端收到旧结构保存请求时统一规范为报告引用，不把旧正文重新存回会话。

- 正常成果：会话卡片可以打开当前成果，也可显式查看生成时的历史版本。
- 回收站成果：会话卡片显示“已移入回收站”和到期时间，提供进入回收站/还原入口，不展示缓存正文。
- 永久删除成果：保留“成果已永久删除”及来源运行入口，不展示原正文，不显示还原。
- 原运行与引用记录仍可用于审计；来源文件不存在时引用提示缺失，不因此阻止成果还原。
- 删除成功后失效正常列表、回收站、详情、版本和图片缓存，关闭正在显示的正文或切换到删除状态。
- 还原成功后重新取数，不沿用删除前缓存。跨标签页在窗口重新获得焦点时重新验证状态；打开的回收站详情须在到期时失效。

## 8. 界面与用户旅程

沿用“成果”一级入口，在该页提供“成果 / 模板 / 回收站”三个视图，可用 /artifacts?view=trash 与 /artifacts?view=templates 表达，直接打开和刷新保持位置。不再增加一级导航。

### 正常成果

- 保留全部成果/当前会话、类型筛选和卡片预览。
- 卡片菜单、详情操作区都提供“移入回收站”。明确显示将保留 7 天。
- 移入操作可直接执行，成功提示“已移入回收站，保留至……”，提供“撤销”；撤销调用还原接口。
- 生成中的成果禁用删除并解释等待任务结束，后端仍执行同一限制。
- 卡片使用容器加独立打开按钮、菜单按钮，保持键盘可达，不嵌套 button。

### 回收站

- 默认展示所有会话的已删除成果，可筛选类型/搜索标题；每项显示来源会话、原业务状态、当前版本、删除时间与到期时间。
- 详情允许只读预览及查看原引用；编辑、版本创建、替换图片、导出和继续生成须先还原。
- 提供“还原”和“彻底删除”。还原不要求知识库仍在线，也不要求模板仍未归档。
- 手动彻底删除需要一次明确确认，说明会删除全部版本和独占附件且不可恢复；不要求重复输入标题。
- 到期项不可还原，不通过改浏览器时间绕过检查。
- 首版完成单项完整旅程；批量选择和清空整站不作为核心删除的前置。

### 模板视图

复用现有模板列表、预览、草稿编辑、发布与归档/还原接口。任务页可保留固定模板选择和跳转入口，移除重复的完整模板管理 UI。发布状态与归档不更名成“删除”，不伪称支持 7 天自动销毁。现有规则是：自由选用已归档模板生成报告会被拒绝，已发布任务的固定模板版本仍可运行；复用 [tests/test_custom_templates.py](../tests/test_custom_templates.py) 中的既有旅程验证路径迁移后规则一致。

## 9. API 契约与并发

具体类型纳入现有 api.ts 和 OpenAPI。以下是新增契约，实施前与现有调用方一起调整：

| 接口 | 行为 |
| --- | --- |
| GET /api/artifacts?view=active | 默认正常成果；保持会话、类型、状态筛选语义 |
| GET /api/artifacts?view=trash | 仅未到期的回收项，按删除时间倒序 |
| GET /api/artifacts/{id}?include_trashed=true | 回收站只读预览；正常请求不能绕过删除状态 |
| DELETE /api/artifacts/{id} | 携带 If-Match 的 revision，将正常成果移入回收站 |
| POST /api/artifacts/{id}/restore | 携带 If-Match；未到期时原样还原 |
| DELETE /api/artifacts/{id}/purge | 携带 If-Match；仅回收项可手动彻底删除 |

- 正常详情与回收详情均返回 revision、trashed_at、purge_after 和生命周期；服务端 ETag 与 revision 对应。
- 修改缺少 If-Match 返回 428，revision 过期返回 412；旧标签页不能覆盖删除/还原/新版本操作。前端 If-Match 使用服务端 ETag，包括 HTTP 要求的引号。
- 删除/还原成功返回更新后的元数据。revision 有效时，同状态重复操作不改时间或创建版本；旧 revision 仍返回 412，客户端先取最新状态再决定是否重试。网络超时不能导致第二次点击刷新回收期限。
- 手动 purge 重复请求若已存在永久删除标记，返回已永久删除的幂等结果；不再执行资源删除，也不能恢复。
- 已知被删除的 ID 返回 410 和结构化生命周期原因；未到期时可返回删除时间与还原提示，但不夹带正文。未知 ID 返回 404。
- 生成中删除、回收项编辑/导出、正常成果直接永久删除等状态冲突返回 409。
- 编辑版本、图片替换、标题修改等已有写入口也接入 revision 校验；不能只保护删除接口。
- 到期检查、revision 比较和状态写入使用同一个数据库事务，BEGIN IMMEDIATE 保证清理与还原只能有一个胜者。
- 新增视图固定保持默认 active，不能让旧列表请求无意返回回收内容。
- 回收站超过现有 200 条上限时提供稳定游标分页；不能将第一页当成整个回收站或按可见页判断过期数据。

旧报告读接口、导出、图片、版本列表、自动修复、模板引用跳转都需核对；成果生命周期检查必须在存储/服务层统一，不能依赖前端隐藏按钮。

## 10. 彻底删除与附件回收

一次事务完成：校验状态与期限/确认 → 写最小删除标记 → 删除成果版本、引用、参数和成果记录 → 清理不再被任何成果版本引用的图片。

图片按 sha256 在同一数据库共享。判断“无人引用”必须包括其他正常成果、其他回收项和它们的所有历史版本；不能只查当前版本。共享图片保留到最后一个引用永久删除，回收项仍计入引用。

- 原知识库 PDF、Markdown、原图不删除；成果内保存的图片副本按上述规则清理。
- 后端当前导出直接生成字节，首版无需建立新的持久导出缓存。如果后续已有缓存，必须有成果 ID 归属并纳入清理。
- 物理清理失败要留下可重试状态或清理日志，不能先报告成功再静默保留正文。SQLite 事务失败回滚，后续服务启动/周期任务可重试。
- 只处理明确归属于成果的行或附件；不要按用户标题、文件名通配符或未核对的绝对路径递归删除。
- 本方案不引入 SQLite VACUUM 或安全擦除承诺；应用层不可恢复与磁盘取证恢复是不同承诺。

自动清理在 FastAPI lifespan 中启动一次，关闭服务时取消并等待结束。先执行启动清理，再每小时扫描到期索引；不使用前端计时器、不要求安装 cron、不新建独立清理服务。测试注入时间函数即可，不等待真实 7 天。

## 11. 迁移、备份与回退

迁移作为独立步骤，在服务停止写入时进行；不是第一次打开成果列表时偷偷迁移。

1. 保存并验证现有应用状态的成组备份，包含 artifacts.sqlite3、reports.sqlite3、custom_templates.sqlite3、workspace.sqlite3、runs.sqlite3 及原图片数据。不要直接复制正在写入的 SQLite 主文件而遗漏 WAL。
2. 在临时目标目录建立新结构；导入成果/模板，收敛历史报告及 ID 映射，转换会话内嵌报告。保留所有用户版本与已有未核验标记。
3. 检查正文哈希、版本数量、当前版本、图片可读性、引用及任务绑定模板版本、生成参数、历史地址、会话关联和运行幂等关系。
4. 校验通过后一次切换程序路径。旧运行时正文数据文件退出使用并移入有明确位置的离线备份；不同时运行新旧存储，不加模式开关。
5. 迁移中断可重入；切换失败恢复整个备份集合。开始新版本写入后不能直接回旧应用并假设仍能理解新删除状态，应先停止服务、导出新增数据并明确回退范围。
6. 离线备份不接受 7 天回收策略自动删改；用户恢复旧备份会恢复备份当时的状态。需在备份说明中写明这一点，不宣称删除能穿透用户离线备份。

不伪造历史 report 的 run_id，不把迁移标记为重新生成，也不为了兼容陈旧代码保留第二条正文读写链。

## 12. 实施批次与代码位置

| 批次 | 工作与依赖 | 交付依据 |
| --- | --- | --- |
| A：收敛存储 | ArtifactStore 报告身份/参数、生成状态与删除标记；迁移报告、模板路径和会话引用；删除 ReportStore 持久化及 legacy 合并/回补 | 迁移后旧 ID 回读同一成果，用户版本不丢，迁移可重入、可回退 |
| B：生命周期 API | 删除、只读回收预览、还原、永久删除、revision、图片回收；旧接口同样校验 | 真实 API 删除→还原→彻底删除，不存在绕行与回补 |
| C：管理界面 | 成果/模板/回收站视图，卡片与详情动作、提示、焦点、缓存、会话已删除状态 | 浏览器完整旅程；正常列表和会话入口一致 |
| D：到期清理与交付 | 启动/周期清理、期限边界及并发，备份说明和文档同步 | 不等待 7 天的真实数据库场景，重启清理、共享图片保留、原文件不误删 |

主要改动范围：src/artifacts.py、src/main.py、src/reports.py、src/workspace.py、src/agent/config.py、src/custom_templates.py；frontend/src/api.ts、conversation.ts、workspace.ts、components/ListingViews.tsx、Inspector.tsx、MessageView.tsx。前端缓存沿用项目 Query/现有刷新模式，不引入新的状态框架。

A 到 B 是一个可验收的后端闭环，C 到 D 是用户功能交付；不能只发布一个“删除按钮”而把迁移、防回补或到期清理留作未明确接收的后续补丁。

## 13. 最小验收与反证

扩展现有 tests/test_artifacts.py 和 tests/browser_artifacts_live.py，不逐字段新增同义单元测试；历史报告关联复用现有报告测试，模板路径迁移复用自定义任务/模板旅程。

| 验收旅程 | 能发现的真实失败 |
| --- | --- |
| 生成图文报告→编辑版本→移入回收站→刷新/重启→还原 | 内容、版本、引用或图片丢失；删除状态不持久 |
| 从回收站只读预览→还原→编辑→导出 | 回收期内容不可读；还原变成新 ID 或伪核验；正常功能不能恢复 |
| 删除后读取旧 report 地址、原会话、版本/导出/图片，并重发同运行请求 | 第二条读路径仍暴露内容；自动修复复活成果 |
| 期限前一秒还原；恰好到期；服务关闭跨过期限后启动 | 期限口径错、边界可恢复、离线后不清理 |
| 双标签页编辑与删除；还原与清理竞争；重复点击删除 | 陈旧请求覆盖状态；时间被重置；并发导致半删除 |
| 两个成果共享一张图，先清理一个，再清理最后一个；保留另一成果历史版本 | 附件提前删除或永远泄漏 |
| 有/无 run_id 的历史报告迁移，包含不同的初始正文与用户版本 | 假来源、卡片重复、旧版本丢失、正文覆盖 |
| 删除回答快照，检查原聊天和知识库文件；模板归档后执行固定版本任务 | 误删源资料/聊天；模板管理破坏任务契约 |

手动彻底删除增加一条浏览器确认与不可恢复路径；到期/并发放在同一真实数据库旅程控制时间，避免真实等待或只 Mock 返回成功。

完成条件：正常列表、回收站、旧地址、会话、导出与后台任务均使用同一生命周期；回收期原样还原；到期或手动清理后不能回补；共享附件及来源资料不误删；新路径备份恢复有效。前端构建、受影响 API 与上述浏览器旅程应在集成后的代码上通过。

## 14. 设计复核结论与实施前核对

本方案已对照当前源码处理重复正文、历史回读、会话缓存、模板依赖、共享图片、期限、服务停机和并发冲突，没有用开关叠加新旧生命周期。当前只完成文档审查，未运行迁移、代码测试或清理原型。

进入实施前还须从实际数据核对：历史报告是否有找不到初始版本的冲突、会话分支的实际报告结构、图片缺失情况和任务对已归档模板的固定版本依赖。若初始报告与已存版本无法确定对应关系，不猜测覆盖，保留数据并给出具体记录及可选迁移方式。

7 天期限、只读回收预览和单项永久删除可直接按本指南细化实现。模板的 7 天销毁、独立于 STATE_DIR 的仓库根 .artifacts、全盘擦除和全集成果文件同步改变现有契约，不能作为本次简单附加项混入。
