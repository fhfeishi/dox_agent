## 二、页面分工

### 首页：直接开展与接续工作

用户与管理员首页以新建对话、查阅资料、存量分析、审查申请书、情报分析为入口。紧凑状态行替代大面积宣传与重复统计卡；最近报告位于入口下方，个人历史保留于后。报告点击打开现有正文预览；审查完整报告沿用其独立工作页。

领导首页延续已确认的领域卡片，不重新塞入近期任务。业务工作仍可从工作台入口进入。

### 领导概览：可解释的研究版图

建设概览以短标题、克制深色页头、领域分布卡片和实际项目数为核心。条形长度仅表达库内项目数量的相对规模，不代表质量、进度或成熟度。领域卡片展示真实立项范围与应用方向，点击进入同一概览的领域分析；视角切换原位进行，不累积浏览器历史。专题保留场景、问题、技术谱系、路网、年度和项目关系，证据继续在右侧查看。

项目总数为各库统计之和，未跨库去重；缺失数据不补零作结论。直接经费与批准资助金额保持各自口径。

### 管理员概览：维护优先、细节完整

顶部为运行状态和待办；下方为资料／项目、四维覆盖、场景问题、技术条目、立项年份与生成时间。待办自身滚动，避免压住全库表格。技术谱系缺失、过期、未归类和项目身份待核对均可查看。任务全量计数采用已有汇总接口；当前列表可能受接口限制，不能冒称全部失败任务明细。

任一请求失败都显示读取失败，不能显示“暂无需要处理”。四维各自的完成项目数不能推断共同交集，直接展示四维分项数字，预览与表格保持一致。

## 三、导航与交互

1. 全局顶栏、角色权限、五个业务模块及成果页保持已有稳定位置。
2. 主业务切换使用路由；领域、视角等阅读筛选替换当前 URL 参数，刷新可恢复，返回不需逐项撤销筛选。
3. 当前页面的文档、引用、模板、成果详情复用右侧容器；不新增一套弹窗或跳转中转页。审查长报告保留既有独立页面。
4. 资料库维持“资料文件／技术研判／年度分布／项目关系／管理”。领导默认技术研判，其他角色默认文件。
5. 右侧页签支持方向键、Home、End，只有当前页签进入 Tab 顺序；保留关闭与返回操作。
6. 明确按钮层级：每块一个主要行动，预览和导航为次要操作，删除保留危险色。选中与悬停靠边框、底色、文字变化，不让卡片移动。
7. 不新增权限隔离、审批、任务流程配置或后台自动重算。沿用已有数据与服务。

## 四、视觉语言

蓝灰主色承载导航、选择和链接；红色仅用于失败／危险，绿色仅用于实际完成。深色大面积仅用于领导建设概览的开场区域，用户工作页保留白底与紧凑标题。统一可见键盘焦点，常规过渡约 140 毫秒，降低动态效果偏好下取消动画。右侧面板减轻阴影，避免多个竞争视觉中心。

不把所有模块重写成新的组件框架；优先调整共享色彩、焦点、面板及首页、概览，保留已验证的报告、审查、资料列表和图谱结构。

## 五、验收与实施记录

验证的真实失败方式：角色页面混淆、视角切换污染返回历史、统计加载失败被当成零、窄屏溢出、资料对话跳出当前范围。扩展现有 tests/browser_library_documents.py，复用真实临时服务与资料；仅问答模型使用替身，失败状态使用受控 503。不增加镜像实现的单元测试。

本轮修改：用户首页层级、领导建设概览卡片、管理员状态与覆盖口径、相关库预览、概览原位技术谱系、共享页签键盘操作、颜色／焦点／减弱动画；React 运行时独立打包，保留功能页懒加载。验证结果在收尾时补录，不将静态构建当作界面验收。

## 六、接续工作与交互状态（第二轮扩展）

### 页面之间的职责和入口

首页是开始与接续；概览是归纳和维护；资料库是事实与检索范围；分析／审查／情报是生产工作台；成果是统一收录与回看。入口带上用户明确选择的范围，不能点击“未完成”却仍显示所有报告。本轮将首页生成中、未完成计数连到对应成果状态。

长审查报告保留独立页面，这是阅读密度需要；从成果进入时带上当前列表地址，并提供明确的返回入口。直接打开审查链接也能回到成果。仅接受本地成果地址，避免外部返回链接。报告专题切换保留返回参数。

### 状态保存边界

| 状态 | 所属位置 | 恢复行为 |
| --- | --- | --- |
| 成果视图、分类、标题、来源库、生成状态 | URL 查询参数 | 刷新、查看审查报告并返回后保持 |
| 概览领域和视角 | URL 查询参数 | 原位切换，替换历史记录 |
| 原文和成果预览 | 当前右侧面板 | 不跳主页面，关闭回到触发控件 |
| 报告编辑正文、任务输入 | 原有编辑／任务存储 | 本轮不另建状态副本 |
| 列表滚动位置 | 页面当前实例 | 不承诺跨刷新或离开页面恢复 |

查询与分类不是新的导航层级，更新不累积浏览器历史。清除筛选同时还原分类、搜索、资料库和状态，保留报告／周期总结所属视图。来源库已移除时仍能辨认当前筛选并主动清除。

### 信息密度和可达性

成果列表保留标题、类型、状态、日期、版本和资料库；生成人按原需求留在详情，不在每一行重复。状态筛选区分已完成、生成中、未完成与草稿，生成中涵盖排队及执行，不能将失败算完成。

侧面板关闭时使用 inert，确保隐藏控件不进入键盘顺序；打开将焦点送入面板，关闭返回原触发控件。保持非模态设计，不增加阻断主工作区的遮罩。已有 Esc 和面板内部返回复用，不另外叠加关闭逻辑。过渡缩短至 150 毫秒，服从减弱动画偏好。

### 异常与恢复

首屏失败显示原因与“重新加载”，不同时无限显示加载中。刷新失败可保留已读内容并显示错误，不伪装成空列表。空筛选结果提供统一清除入口，不要求用户逐项撤销。加载、无数据、无匹配、失败应是四种不同状态。

### 本轮验收范围

扩展已有 browser_review_simple 流程：模板预览焦点与 Esc 返回、隐藏面板不可交互；三份审查结果筛选后刷新、打开报告、刷新报告、返回原列表；无匹配清除；成果读取 503 后原位重试；窄屏无横向溢出。使用真实临时服务、存储、导出与浏览器，模型仍为受控替身。保留上一轮证据，新增结果另记，避免宣称所有历史需求全部完成。
