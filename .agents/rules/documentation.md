# Agent 文档撰写规范 (Documentation)

**核心宗旨**：用最少的必要文字，建立可理解、可使用、可维护的知识结构。文档服务于用途，而非套模板凑字数。

## 1. 组织与维护原则
- **用途先导**：明确读者是为了理解、实施、排查还是追溯。不套用统一的僵化摘要模板。
- **同类合并**：优先在现有文档与章节中更新与增补。共用规则只写一次，场景只补差异。禁止因单次修改随意新建版本文件。
- **最小充分信息**：剔除泛泛的背景介绍、空洞评价和无增量的过程；保留复现、实施与追溯所必需的条件、决策理由、失败尝试与边界。
- **严禁信息混淆**：事实、推断、假设不可混淆；拟议（Proposed）、已采纳、已实现、已验证状态必须清晰标明。

## 2. 四类文档专属结构
- **知识与研究**（让人理解并复用）：
  `问题 -> 核心解释与关系 -> 例子/方法 -> 适用边界`
  区分作者声称、实验支持与实践推断；保留结论成立的前置条件，不强行抹平冲突。
- **开发与排查记录**（让人还原并接续）：
  `事件/日期 -> 问题 -> 实际变化与原因 -> 结果/证据 -> 接续点`
  只保留改变判断的关键失败尝试与排除理由；长日志另存，正文仅留关键定位结论。不粉饰历史。
- **设计与契约**（让人实施并核对）：
  `目标/范围/状态 -> 对象与关系 -> 行为及约束 -> 边界 -> 示例与验收`
  现有实现与拟议设计严格区分；状态变更写明最终如何回读；只展开影响目标的异常分支。
- **计划与 Agent 指引**（让执行有限且可验收）：
  `适用条件 -> 目标与边界 -> 行动规则 -> 验收/退出条件`
  将“优雅、严谨”转化为可观察标准；只细化足以行动的下一步，不盲目展开无依据的长链条分支。

## 3. 审查与交付检查
- **审查摘要是入口，不替代正文**：摘要直奔当前结论、关键理由与待决事项，严禁为了形式强凑风险数量。
- **三项交付检查**：
  1. **逻辑闭环**：目标、前提、依赖与结论是否一致？事实与推断是否分清？
  2. **信息充分**：是否删除了关键限制条件？读者能否据此行动/复现？
  3. **去重更新**：是否已合并至既有主题？有无冲突、失效表述？
