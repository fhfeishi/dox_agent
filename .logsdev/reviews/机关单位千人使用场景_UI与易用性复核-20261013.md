## 一、结论与前次报告的修正

当前系统已经具备可继续试用的角色入口、资料库工作区、分析与审查流程。最新阶段的主要问题是“同一资料库内容分散在多个视图、切换容易丢失阅读重点”，不应通过继续增加页面解决。

建议采用：**统一资料库工作区，保留资料库卡片；选库后在原工作区切换分析视角；图表明细和原文统一右侧预览；谱系提供可恢复的专注画布。**

前次报告中部分现状已被后续实现替代：

- 已有“我的工作”、创建人记录、作者或管理员发布、领导已发布报告视图，不再描述为只有全局报告入口。

- 已有部分服务端管理动作限制，不能再称“只有账户管理有限制”。

- 已取消首页并调整角色落点，旧 /leader 直接访问失败不是本次隔离服务上的现存结论。

- 审查摘要列表、空闲轮询、重复审查合并和服务端周期统计已优化，应继续沿用。

- **用户已确认现阶段不做个人/部门数据可见范围隔离**。本轮不把它重新设为界面开发前置条件。创建人和发布权限不等于数据隔离；约千人正式部署再单独验收访问边界。

- 用户确认先改层级提示词、不立即重生成11库。因此旧场景数据仍可能受原配额影响；既不能假称已纠正，也不能未经授权批量重生成。

总体取舍：先完成 2012 要求的统一浏览与图表点选，保留已有功能；避免同时重构账号、数据归属和业务分析模型。

## 四、针对最新 query 2012 的优化方案

### 4.1 “一个界面”定义为同一工作区，不是全部内容同时铺开

保留顶栏与资料库工作区，工作区有两个可恢复的状态：

**全部资料库：**

- 分组、搜索和资料库卡片；卡片保留库名、一句说明、报告份数、必要状态。

- 卡片主操作“打开”；信息预览可点击说明/信息按钮。

- 管理员可新建库、管理分组，卡片“更多”中改名、说明、移动或删除。

- 普通用户与领导使用相同卡片组件，按当前服务端管理规则隐藏维护操作；“具有增删改查”不等于所有角色都能删除。

**当前资料库：**

- 原工作区内展开库内容；顶部“全部资料库 / 当前库名”、库切换入口和当前视角。

- 关闭当前库返回之前的卡片位置、搜索与分组，而不是回到重置后的首页。

- 左侧库列表可作为快速切换工具，默认是否展开按屏幕空间决定；不用卡片和完整列表长期占据两份空间。

- 允许URL表达库、视角、年份、选中节点，使刷新和浏览器返回可恢复。要求是“不打断思路”，不是禁止任何路由变化。

建议布局：

    顶栏：我的工作 / 对话 / 资料库 / 存量分析 / 资料审查 / 情报分析
    工作区工具：全部资料库 › AI与医疗     切换资料库     管理（按角色）
    内容区域：资料概况 | 研究分析 | 资料文件
    研究分析内：技术谱系 / 场景 / 问题 / 技术 / 成果；更多：年度分布 / 项目关系
    主阅读区：只展示当前视角
    右侧：本次点选的库信息、年份报告清单、项目、原文或报告

推荐将顶层收为“资料概况 / 研究分析 / 资料文件”三个区域；只有进入研究分析才显示已有五个板块，年度分布和项目关系放在该区的“更多视图”。原谱系总览的信息复用于资料概况，不重复维护或计算。此为待实施的信息架构建议，不改变五个研究板块都要保留的已确认要求。

### 4.2 谱系尽量铺满，但保留方向感

当前页面先展示大段总览和卡片，五级谱系在其下；画布自身较高，但用户必须向下滚动才能到达，侧栏与详情又分摊宽度。增加高度不能独立解决空间问题。

建议：
1. 点击“技术谱系”直接显示谱系主体，总览和路网成为按需切换/收起的内容。
2. 增加“专注图谱”按钮：临时收起库目录、非必要说明和统计，保留当前库名、视角与退出按钮。
3. 两窗格等高、支持拖动分隔；高度按实际可用空间计算，避免固定大高度造成多层滚动。
4. 提供“适应画面、放大、缩小、恢复位置”，图内拖动不选中文字。
5. 专注状态内仍可点技术联动详情，不能为了铺满只剩一张孤立图。
6. 返回恢复原侧栏状态、选中节点和画布缩放；窄屏采用图与详情切换，不强塞等宽双栏。
7. 节点保留同层参照、只展开当前分支；原需求的R2–R6层级标记保持，专业名称与简短解释的命名规则不在本轮推翻。

验收：1366×768、1920×1080及125%缩放下实看节点字号、点选与返回；“无横向溢出”不能代替节点可读。

### 4.3 年度柱子点击打开右侧“当年资料”清单

当前柱子只执行 onYear，属于筛选行为；用户现在要求的是点击后立即得到可阅读明细。

建议一次点选完成：

- 图中高亮年份，右侧打开“2022年 · AI与医疗”。

- 头部列“报告N份、涉及项目M个”，按立项年归属；明确这不是当年发布的新报告量。

- 清单按项目分组，列该项目关联的每份资料，支持在清单内搜索。

- 点资料进入原文，点项目进入项目详情；面板返回到年份清单，不丢年份。

- 关闭面板保留主图年份选中；“清除筛选”恢复全库。

- 柱子必须可Tab聚焦、Enter/空格触发；零值年份提示“本年无纳入资料”，不打开空白面板。

- 年份未知、身份待核对的资料另外提供入口，不把它们默认为0或静默计入某年。

关于“数量”：沿用1842最新要求，以报告文件份数作柱高；项目总数按身份去重显示，二者不混称。

资金图继续采用项目直接经费散点和年度平均，保留样本量。重叠点点击后列出该位置的多个项目，不用数据偏移伪造金额。年度平均线只连接有相邻年份有效数据的点；缺失年应断开或明显标示缺测，不能让连线暗示已有观测。

### 4.4 自动选库：默认有效、过程清楚、人工选择不被抢回

当前新浏览器默认开启；手选库会关闭并保存在本地，历史偏好可能仍是关闭。

建议不在每次打开页面时强制覆盖用户选择：

- 新任务默认自动；用户明确手选则保持固定范围，旁边可一键恢复自动。

- 发送前显示“按问题自动选择”；选定后显示库名和“更换”，无需用户先了解全部库。

- 低把握/多领域问题展示少量候选，而不是要求用户在11库中盲选。

- 路由接口失败不能默默沿用上次范围。当前代码 catch 后直接继续使用原库，应至少明确提示实际范围，避免用错库仍看似回答正常。

- 涉及跨领域对比时，允许推荐两个范围，不把默认一个库当所有任务的绝对上限。

- 默认开关、范围选择、回答依据是不同层次；此轮只实测了默认勾选与读取，未据此宣称自动路由质量达标。

## 六、对1637—1914的进一步回答：近期工作与总结怎样才有用

### 6.1 工作对象是资料与分析任务，不是自动管理科研项目

系统可客观说明：

- 哪些领域新增或更新了分析报告；

- 哪些材料正在审查、失败或缺少结论；

- 多份报告有哪些共同关注点、不同判断和证据缺口；

- 有哪些值得补充资料或继续分析的问题。

系统不能仅凭任务状态或报告篇数推断实际科研项目完成百分比、人员工作绩效或项目技术成熟度。周/月总结应称“资料分析工作总结”，避免误写“科研项目进度总结”。

### 6.2 周期必须区分“形成、更新、发布”

现有普通成果主要按 updated_at 筛选、审查按 finished_at/created_at 筛选，发布状态只是过滤条件。因此“本周工作”不一定等于“本周新生成”或“本周发布”。

建议：

- 普通用户/管理员：默认显示本期形成及更新，分别标注；旧报告修改不计成全新成果。

- 领导：默认显示本期发布成果，按 published_at；已有报告的新修订应标“更新发布”。

- 同一材料多次同类审查合并计数，仍能展开每次记录。

- 周/月/季度/年度总结保存明确起止时间、时区、统计口径和发布版本；再次查看不重新计算旧总结。

- 总结自身不反复纳入下一轮工作量，避免总结生成总结、数字膨胀。

### 6.3 图表选择要服务问题

保留用户要求的雷达图，但它表示各类数量分布，不是综合评分；紧邻总数、未判定数和重叠归类说明。报告主题占比/数量更适合横条，工作变化适合时间柱图；只有一个类别无需画图。

“结论之间的联系”优先用短表：
主题｜共同结论｜不同意见｜各自依据｜待补材料。
模型解释必须引用参与总结的具体报告版本，不能为了形成观点给出未经证实的优劣评价。

员工自写报告可作为后续明确的“上传工作报告”入口，但必须有标题、作者、日期、来源文件和发布状态，不能借用情报分析输入后就假称已归档为工作成果。本轮未验证自写报告直接导入、发布并参与周期总结的完整链路。

## 八、D2取舍建议：两个入口，复用一个提问流程

不直接删除“点选提问”或存量分析：

这是一项供确认的交互取舍，不应把“需要更简单”自动解释为删除已要求的任务功能。

## 十一、进一步细化：让最新需求成为可实现的交互契约

本节补充前文4—9节，针对最新2012条进行方案细化，不是新增实现或测试通过声明。

### 11.1 统一资料库工作区：明确两个状态与三级信息深度

“全部资料库”和“已选资料库”是同一工作区的两个状态，不同时铺满两套内容。阅读深度依次为概况、分析、证据；不要求用户一进入就看到图谱、文件表和所有管理按钮。

| 状态 | 首屏内容 | 主要操作 | 返回规则 |
| --- | --- | --- | --- |
| 全部资料库 | 分组、搜索、资料库卡片 | 打开资料库；管理员新建与管理分组 | 从具体库返回后恢复分组、查询和滚动 |
| 当前库·资料概况 | 名称与说明、报告份数/项目数、更新时间、主要方向及已有分析是否可用 | 查看研究分析、查看资料文件；右侧看信息 | 返回全部资料库，不重置浏览偏好 |
| 当前库·研究分析 | 当前所选的一种分析视角 | 切五个研究板块、更多视图、专注图谱 | 切视角保留当前库；返回恢复该视角选择 |
| 当前库·资料文件 | 文件清单、搜索和处理状态 | 查看原文；管理员上传与维护 | 关闭原文回到文件列表原位置 |

这不是新增三个一级业务模块。领导、管理员和普通用户使用同一个库内容组件，区别在入口默认落点和允许的操作：
- 领导建设总览点击库：先右侧看简要信息，再由明确按钮进入统一工作区。
- 管理员待办点击库：先预览问题及处理入口，用户点击“处理”才进入对应文件或管理状态。
- 普通用户点资料库导航：先见卡片。上次选过库可提供“继续查看”，不直接替他选第一个库。
- 进入同一个库后，不为不同身份另生成一份统计或复制一套谱系。

### 11.2 卡片字段要稳定，管理操作不要分散

卡片默认只显示：库名、一句内容说明、报告份数、已识别项目数和需要用户注意的异常。没有说明就显示“暂无说明”，不要自动用模型生成未核实的库定位。

资料库分组是展示组织，不改变检索范围或项目身份。一个库的卡片、左侧快速切换和领导预览读取同一份名称、说明和计数。

管理员“更多”菜单集中：编辑名称与说明、移动分组、上传资料、移除/删除。沿用后端真实删除语义并明确告知影响，不额外创造一个并未支持的“资料库回收站”。用户取消时不改数据，操作失败保留输入和原卡片。清理索引属于维护动作，不与“删除资料库”混为一个按钮。

### 11.3 同区切换与URL并不矛盾

建议用既有路由与查询参数表达“库、当前区域、分析视角、年份、选中对象”，不另存一套互相打架的导航状态。

必须保存：卡片查询和分组、所选库、分析视角、主区滚动、谱系选中路径。画布缩放和左右分隔比例只属本机偏好，不写成业务事实。

切换库时清除旧库的项目/原文/节点选择；保留当前视角仅当新库支持。不能出现主标题是医疗库、右侧仍显示机器人项目却未标来源。多文件跨库对比需另有明确任务范围，不把普通浏览当成对话选库操作。

### 11.4 右侧面板遵守“一次一个对象、逐层返回”

年度柱子、经费散点、资料库信息、项目、原文和报告共用已有面板，不各开一个抽屉，也不层层覆盖弹窗。

典型链路：
1. 点击年度柱子 → 该年资料清单（报告N份、涉及M个项目）。
2. 点击清单中的资料 → 原文；标题标实际文件与来源库。
3. 返回 → 原年份清单，恢复清单滚动。
4. 关闭 → 回到主图，保留选中年份。

点另一年度柱子应替换本次明细上下文，而不是不断累积无法理解的历史栈。点击“清除筛选”后关闭关联年份明细或明确同步到全部，不能留下过期条件。

统计口径必须落实到对应清单：点击显示N份时，明细应能列出同一集合；分页只改变已显示数量，不改变总数。资料已删除/更新导致数量变化时提示并刷新，不静默补成旧数量。

### 11.5 谱系“铺满”是专注模式，不是永久占据屏幕

建议首期在既有分隔与缩放控件上加一个“专注图谱”，不更换图形库：
- 默认模式仍便于切库、查资料；专注模式收起辅助目录与说明。
- 保留库名、面包屑、恢复按钮和必要图例，主画布用剩余可用高度。
- 右侧技术详情默认保留且可调宽；查看原文时复用全局面板，避免同时出现两个右侧抽屉争空间。
- 全局原文面板关闭后，恢复技术详情和画布位置。
- 谱系与路网二选一展示为主画布；总览按需返回。不同视图共享选中技术ID，不因切换重新归类。

“内容未生成/已过期/来源不足”的提示保留一行即可，展开看原因。用户缺少管理权限时不出现“重新生成”主按钮；缺少数据时不以空知识节点冒充已收录技术。

### 11.6 自动选库的四种情况

| 情况 | 建议行为 |
| --- | --- |
| 单一领域清楚 | 自动选库，并在问题/结果旁显示实际库名 |
| 两领域对比明确 | 按任务能力推荐两个范围，显示名称；不能自动截成一个库 |
| 问题模糊 | 用少量候选或一次简短确认辅助选择；允许沿用当前库但必须明示 |
| 路由服务异常 | 保留问题文本，显示实际备用范围；不得悄悄改范围后继续声称自动选择成功 |

用户主动指定“仅用此库”优先于自动推荐。已有按文档限制的分析不因新问题被扩展到整库。自动范围变化前后的来源应随任务保存，不能只在短暂Toast里出现。

先用代表性问题验证推荐与失败行为；不要为了“默认自动”再调用一次模型对所有简单问题重新分类。现有确定性/检索路由能满足时继续复用。

### 11.7 周期总结的“有用”要落实到材料层面

领导关心“本期关注什么、得出什么结论、还有什么尚未说明”；管理员关心“材料和证据还缺什么、哪些分析可以继续”。两者都不等于根据报告数量评价员工能力。

建议总结固定四块：
- 本期已发布的主要结论及其来源；
- 多份报告的共同点、分歧与各自条件；
- 尚未形成结论的分析事项；
- 需补资料或可继续开展的分析。

“未形成结论”必须来自实际任务/报告状态或明确记录，不能靠报告没有提到某话题就推定未完成工作。领导若只读取已发布结果，未发布任务可只给约定范围的聚合状态；未经明确设计，不为凑“进行中”信息扩大领导报告输入范围。

周期版本建议：发布时记录具体成果版本；发布后编辑产生未发布修订，领导仍读已发布版本，作者明确再次发布才替换。此为后续要验证的契约，不宣称现有 published_at 已实现完整发布快照。

对“近期工作按更新日期还是发布日期”的取舍：默认领导按发布、管理员按形成/更新并标类型；提供简短口径说明，不向普通用户展示多组技术日期开关。
