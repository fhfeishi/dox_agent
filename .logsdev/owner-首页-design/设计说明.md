# 首页「资料库概览」改版 · demo 说明

> 产物：`library-overview-demo.html`（单文件，无依赖，双击可看）
> 数据：`.knowledge` 下 11 个资料库的**真实** `lineage.json` / `target/*.json` / `source/`
> 状态：待审核版式，未改动 `LeaderHome.tsx`

## 一、这一版做了什么

把 02「资料库概览」原来的「各领域项目数条形 + 应用方向雷达」，换成一张**积累分布图**：

```
横轴：技术条目数（对数）       → 摊子铺得多宽
纵轴：平均成熟度 0–5           → 沉到多深
圆面积：覆盖项目数             → 规模
```

右侧详情随点选切换：技术条目 / 高成熟占比 / 技术体系 / 成熟度阶梯 / 四维覆盖 / 缺口提示。

## 二、为什么换这两根轴

| 原设计 | 问题 | 新设计 |
|---|---|---|
| 左侧横条 = 项目数 | 与 banner 第 1 屏「领域项目分布」同数据同编码，重复 | 横轴改为技术条目数，banner 没讲过 |
| 右侧雷达 = 应用方向 | 代码注释自认「方向由模型归纳，需人工核对」「一个项目可计入多个方向」 | 换成成熟度，有明确 6 档定义 |
| 无纵轴 | 只能看规模，看不出沉淀 | 纵轴用 `items[].maturity`，真实可算 |

成熟度 6 档名称取自 `src/lineage.py` 的 `MATURITY` 常量，不是自拟：

`0 未判定 · 1 理论与方法 · 2 算法与模型验证 · 3 原型与样机 · 4 系统集成与场景试验 · 5 示范应用与转化`

## 三、真实数据读出来的四件事

| 结论 | 数据 |
|---|---|
| 两个库吃掉大半，但沉得最浅 | 医疗 1,336 条 + 机器人 1,025 条 = 87.7%；机器人 80.8% 停在 0–1 级 |
| 「量深兼备」是空象限 | 没有一个库同时超过 100 条且高成熟占比 > 20% |
| 精细的是小库 | 社会治理 16 条、50% 高成熟；信息智能 17 条、35% |
| 结构缺口比数量缺口更硬 | 机器人「问题」维只有 246/510 份文档有归纳（48%） |

## 四、与现有首页的差异

**删掉**
- 「各领域项目数」横向条形列表（与 banner 重复）
- 「应用方向分布」雷达图（口径不可靠）
- 底部 6 列小资料库卡片（与散点重复，点已可选）

**新增**
- 积累分布图 + 点选详情
- 底部三条读数（全库成熟度 / 体量与沉淀 / 最需注意）
- 「只看待补」筛选：高成熟 < 20% 或任一维覆盖 < 95%

**保留**
- banner（改为静态展示，条改为「底轨 + 填充 + 右对齐数值」，小库也能看出位置）
- 工作台、我的工作

## 五、交互（首页级，刻意克制）

| 操作 | 行为 |
|---|---|
| 悬停散点 | 浮层：条目 / 项目 / 均成熟 / 高成熟占比 / 体系数 |
| 悬停阶梯段 | 该段保持、其余淡到 40%，下方浮层给「档位名 · 条数 · 占比」 |
| 单击散点 | 选中，右侧详情切换（键盘 Enter / Space 同效） |
| 单击「预览资料库」 | 右侧滑出抽屉，看完整摘要 |
| 抽屉内点遮罩 / Esc / ✕ | 关闭抽屉 |
| 单击象限名 / 空白象限 | 弹出该象限的「谁在这里 / 该怎么读 / 分割线怎么定」 |
| 单击口径标注 | 弹出该轴的算法与取轴理由 |
| 单击阶梯段 | 弹出 6 档标尺，并高亮所点那一档 |
| 只看待补 | 淡化非缺口库，其余保留轮廓 |

**没有做**：缩放、平移、右键菜单、双击下钻、首次引导。这些是「领域分析」板块的动作，首页只负责「看懂 + 分流」。

## 五之二、关键口径的交互化（本轮新增）

静态说明文字全部撤掉，改成「悬停给一句话、点击给一套解释」。四条入口：

| 入口 | 触发 | 内容 |
|---|---|---|
| 横轴 技术条目数 ⓘ | 点击 | 怎么算（items 计数、同技术重复计）、为什么用对数（16–1,336 差 80 倍） |
| 纵轴 平均成熟度 ⓘ | 点击 | 怎么算（算术平均）、为什么低不等于差（长尾效应，要看 6 档分布） |
| 圆面积 覆盖项目数 ⓘ | 点击 | 怎么算（编号去重）、为什么半径开方（面积正比于数量） |
| 0–5 怎么分? | 点击 | 6 档标尺：名称 + 判据 + 示例 + 全库分布 |

另外三处嵌在图里：

- **象限名 / 空白象限**：点开给出该象限的成员、怎么读、**分割线为什么切在 100 条与 2.5**（100 落在条目数断层上；2.5 是「算法验证」与「原型样机」的中点）
- **阶梯段**：悬停出单档数据，点击打开标尺并定位到该档
- **四维行**：点开说明这一维在问什么、覆盖了多少份文档、缺的份数意味着什么

**弹窗行为**：锚点定位（上/下自动翻），从锚点缩放展开（cubic-bezier(.16,1,.3,1) 300ms），档位行错峰入场 30ms；点外部、按 Esc、切换资料库都会关闭；滚动时跟随锚点而不是消失；打开期间触发元素带浅绿底，让人知道弹窗从哪来。

> 一条原则：**解释只在被问到时出现**。首页第一眼只留图，术语后面挂一个 ⓘ，想深究的人点开，不想的人不受打扰。

## 七、待你确认

1. **纵轴用均成熟度还是高成熟占比？** demo 用了均值（0–5 刻度直观），但它受长尾影响，大库天然偏低；改用「成熟度 ≥4 的占比」象限归属几乎不变，且不惩罚大库。
2. **9 个小库挤在左半边**是否可接受？现在是真实断层（4–20 项目 vs 510），对数轴已经是最优解；若不接受，只能把医疗/机器人单独置顶。
3. **「只看待补」的判定**（高成熟 < 20% 或任一维 < 95%）会把医疗也算进去 —— 因为医疗成果维 91%。这个阈值要不要调？

## 八、右栏重构与预览抽屉（本轮）

### 8.1 右栏为什么重做

原来右栏是「三个等权数字 + 6 段堆叠条 + 4 条进度条」——像后台监控面板：每块都在报数，没有主次。四维覆盖尤其糟糕：四条等长横条只差 9 个百分点，读不出「哪一维是缺口」。

新的信息顺序按「一眼看清这个库是什么」排：

| 层 | 内容 | 编码 |
|---|---|---|
| 身份 | 库名 + 项目/文档数 | 衬线大标题 |
| 主指标 | 条目数（大）+ 成熟 4 以上占比（次） | 字号对比 27 : 21，低占比转赭色 |
| 分布形状 | 成熟度 6 档**竖向柱** | 柱高 = 该档占比，色阶同标尺 |
| 结构完整度 | 四维**四分环** | 弧长 = 该维覆盖率，缺口画虚线 |
| 诊断 | ⚑ 一行，最多两条 | 赭色左边线 |
| 动作 | 预览资料库 → | 实心绿按钮 |

**四维从条改成环**，是因为四个维度本来就是一个整体被切成四份：看得见"哪一块缺角"。覆盖率 100% 的段连成一个完整圆；低于 99.5% 的那段在环上留一段**虚线缺口**，比如医疗成果维 90.9%、机器人问题维 48.2%——后者缺口接近四分之一圈，不用读数字就知道结构有问题。

**成熟度从堆叠条改柱状**，是因为堆叠条在 300px 宽里每段只有几十像素，hover 都点不准；柱状 6 根各自独立，能看出"尖峰在 1 档"还是"均匀铺开"。

### 8.2 预览抽屉

「打开资料库 →」原本是个假跳转（点了只弹一句 demo 提示）。改成**右侧滑出抽屉**，600px，从锚点按钮位置滑入（`translateX(100%) → 0`，440ms `cubic-bezier(.16,1,.3,1)`），遮罩 `rgba(9,28,40,.30)` 配 `backdrop-filter: blur(2px)`。

抽屉内容（全部取真实 `lineage.json`）：

```
┌ 深色头（带绿色光晕）
│  LIBRARY PREVIEW / 医疗
│  514 个项目 · 517 份文档 · 5 个技术体系
│  1,336 条目   17.7% 高成熟   237 高成熟条目
├ 技术体系构成（按条目数排序，带一句白话说明）
│  医学影像分析 525 ██████████████  ← 主干用主色
│  临床决策支持 371 █████████
│  ...
├ 两列：成熟度分布（大柱）｜四维覆盖（大环 + 图例）
├ 进入场景试验或转化的条目（真实条目 + M5 徽章 + 依据）
└ 只读摘要 · 数据取 lineage.json      在知识库中打开 →
```

四块内容错峰入场（每块间隔 60ms），条形从左侧展开（`scaleX`），环从 0 长到目标弧长。

**数据来源**：新增 `EXTRA` 常量，11 个库 × 6 个技术体系（名称 / 条目数 / 一句 `plain` 说明）+ 各库 maturity ≥ 4 的前 3 条（名称 / 领域 / 档位 / 依据）。全部来自 `.knowledge/*/lineage.json` 的 `categories` 与 `items`，没有编造。

### 8.3 三个库的读法差异（抽屉里最有用的一屏）

| 库 | 抽屉读出来的 |
|---|---|
| 医疗 | 体系高度集中：影像 525 / 临床决策 371 / 信号 199；1,336 条里 237 条（17.7%）做到 M4+，代表条目是「多中心多模态数据库」「泌尿肿瘤一体化平台」 |
| 机器人自动化 | 体系分散在控制理论 242、机器学习 229、运动规划 138；1,025 条只有 22 条（2.1%）到 M4+，四维问题维缺口近一半 |
| 隐私保护 | 5 个体系各 5–9 条，36 条**一条都没到 M4**；空态直接写"全部停在理论与算法验证之间" |

### 9.2 后端为什么必须加两个字段

- **`lineage.maturity`（6 个数）**：原接口只给 `lineage.items` 计数，画不出阶梯与均值。
- **`dimension_evidence`**：原 `dimensions` 是 `fully_processed_projects`——「该维全部文件都处理完的项目数」，医疗四维都是 514/514，全都显示 100%，读不出缺口。`evidence_projects` 才是「材料里真的归纳出这一维」的项目数：医疗成果 467/514（90.9%）、机器人问题 246/510（48.2%），与 demo 的结论一致。原 `dimensions` 保留不动，其他页面零回归。

## 十、第二轮版式（2026-10-21 下午，query 2026-1021 续）

用户反馈：项目数与资料数要更醒目；四维覆盖不重要，不必在预览里再展开；抽屉需要有额外信息；整体配色与布局要更协调。

### 10.1 右栏：把规模提到第一层

原来库名下一行 12px 小字「514 个项目 · 517 份资料」，被压在主指标之下。现在四组数字同构排列，都是「数字在上、标签在下」：

```
514            517
个项目          份资料
───────────────────────
1,336          17.7%
条技术          成熟 4 以上
```

- 项目 / 资料用 `text-page`（22px）衬线，与主指标 28px 形成一档之差，不再是脚注。
- 两行用上下边框分开：上一行回答「多大」，下一行回答「多深」。
- 右栏底色由 `--surface-cool` 改为 `--terrain-panel`（#f4f8f9，与地图空象限同源），底栏读数条同步换色，形成「白（卡头 + 图）／淡青（右栏 + 底栏）」两片分区。

### 10.2 四维：环改成同基线横条

环要读弧度，四条等长弧的 9% 差距几乎看不出来；横条比长度，一眼就能找到短的那条。

- 每行：维度名（2.7em）＋ 8px 条 ＋ 百分比（右对齐）。
- 未覆盖部分铺 45° 斜纹（`.terrain-gap`），赭色，缺口自己会说话——医疗成果 90.9%、机器人问题 48.2%，不再需要读说明。
- 仍然可点，弹原本的四维口径卡。

### 10.3 抽屉：去掉四维，加年度立项

四维是「抽取完成度」，它决定的是「下一步补什么」，属于地图右栏；在预览里再画一遍只是重复。抽屉改为四张白卡，按领导的提问顺序排：

| 卡 | 内容 | 数据 |
|---|---|---|
| 年度立项 | 逐年项目数柱状 + 峰值标注；眉批给经费总额与给出金额的项目数 | `by_year`、`start_years`、`funding` |
| 技术体系构成 | 名称 + 条数 + 细条 + 模型的一句话（`plain`）；默认前 5 个，可展开全部 | `lineage.systems_detail` |
| 成熟度分布 | 一条 100% 堆叠条 + 六行图例（档名 / 条数 / 占比） | `lineage.maturity` |
| 进入场景试验或转化的条目 | 前三条 + M 徽章 + 领域 + 依据原文 | `lineage.top` |

- 头部四个指标：项目 / 资料 / 条技术 / 成熟 4 以上，22px，一眼回答「多大、多深」。
- 卡片浮在 `--page-cool` 底上，圆角 12、间距 12；深色头保留，形成「深头 → 浅底 → 白卡」的层次。
- 体系超过 5 个时出现「展开其余 N 个体系 ↓」，避免第一屏只剩半张卡。

### 10.4 配色收敛

- 全页只保留一个实心绿：预览按钮。筛选按钮的选中态改为浅绿底 + 绿字（`--selected-cool`），「只看待补」用浅赭底 + 赭字，不再与 CTA 抢主次。
- 右栏眉题 `CURRENT LIBRARY` 从 `--muted-cool-soft` 提到 `--muted-cool`，在淡青底上能看清。
- 数据色不变：点藏青、选中墨绿、缺口赭、四维蓝绿绿金、成熟度六级绿阶。

### 10.5 细节

- 图区改为垂直居中，右栏内容更长时不会把图顶到卡片上沿。
- 标签与圆的间距 8 → 10px。
- 预览按钮外层 `mt-auto pt-3`，与诊断条至少 12px。
- 抽屉条目区 `.terrain-drawer-body` 加 12px 间隙。

## 十一、两份存档 demo（2026-10-21 晚）

同一区块的两个版本各存一份，便于对照与回看；两份都是**单文件、内嵌真实数据**，浏览器直接打开即可，不依赖服务。

| 文件 | 对应版本 | 内容 |
|---|---|---|
| `资料库概览-原版.html` | 2026-10-21 之前的 `LeaderHome.tsx`（git `HEAD`） | 左：各领域项目数排行条（可点选切换）；右：所选领域的**应用方向雷达** + 项目/立项/经费眉批；下：6 列资料库小卡（名称、项目数、立项跨度、经费） |
| `资料库概览-积累分布图.html` | 现行 `LibraryTerrain.tsx` + `CaliberPop.tsx` + `LibraryPreviewDrawer.tsx` | 对数条目数 × 平均成熟度 × 开方面积的地形图；右栏「身份—规模—积累—6 档阶梯—四维横条—诊断—预览」；底部三条读数；四类锚点口径卡；右侧 600px 预览抽屉（年度立项 / 体系构成 / 成熟度 / 高成熟条目） |

**可交互的部分**

- 原版：点左侧任一领域或下方任一卡片 → 右栏雷达、眉批随之切换；点的雷达顶点有 `<title>` 提示。
- 现行版：悬停圆点出浮层读数；点圆点切右栏；「只看待补」按口径过滤（`high_share < 20%` 或任一维 < 95%）；点横轴 / 纵轴 / 圆面积、「0–5 怎么分?」、任一阶梯条、任一四维行、任一象限标题，弹出对应口径卡；Esc 或点空白关闭；「预览资料库」滑出抽屉，体系超过 5 个可展开。

**数据与复现**

- `tools/libraries.json` 是从运行中的 `/api/overview/libraries` 原样导出的 11 库数据（`fetch_overview.py`，临时 state 目录 + 真实 `.knowledge`）。
- `tools/build_demos.py` 把该 JSON 注入模板并截图，模板是这两份 HTML 本身（`__DATA__` 占位）。重跑一次即可刷新数据：`.venv/bin/python .logsdev/owner-首页-design/tools/build_demos.py`。

**与原页面的差异（都是 demo 边界，不是设计差异）**

- 没有路由：点卡片不跳转；抽屉底部「进入资料库 →」在 demo 里只作展示。
- 顶部只保留区块标题与 02 编号，没有横幅、工作台与「我的工作」。
- 原版雷达按 `Charts.tsx` 的几何复刻（外圈取 `ceil(top×1.25)` 且不超过项目总数）；少于 3 个方向时退化为横条，和原组件一致。
